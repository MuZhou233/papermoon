# Playbook 人工编辑器

[English](README.md) | 中文

编辑器为 PaperMoon 提供 Playbook 总览和独立详情页，通过 DSH 的认证请求调用[逻辑核心](../playbook-core/README.zh.md)。它不创建 Agent 会话，也不发布、审核或调用模型。

## 页面与创作

PaperMoon 默认打开 Playbook 总览。卡片展示 Playbook、所属项目和最新修订版本。搜索与项目筛选使用分页元数据查询。项目管理支持创建、改名和删除；删除项目会移除所属 Playbook 及其私有数据，仍被其他 Playbook 引用的修订版本会保留。新建 Playbook 需要填写名称、项目和明确的默认语言，新建 Playbook 和添加语言的表单提供 zh-CN、en 预置项，也可手动填写其他精确语言代码。

详情页默认打开最新修订版本，另提供草稿、修订版本和设置入口。草稿中可以切换程序文件与文案条目，两者共用一次保存操作。程序文件支持创建、重命名、删除、语法高亮、查找、撤销与重做。文案条目可编辑键、用途说明及指定语言的译文。空译文与缺失译文明确区分，语言管理不会从其他语言补齐缺失译文。元数据会保留，但不提供编辑入口。

保存草稿时，待保存操作携带读取时的序号一并提交。提交修订版本要求草稿已保存、说明非空，可以选择参考版本和有序编译目标，并自动编译。默认目标为 playbook.js 和默认语言。Playbook 错误会阻止提交，除非明确勾选允许编译失败时提交。开启后仍会编译，任一目标失败时不附带任何产物。空 Playbook 在明确检查或提交前保持未编译。

修订版本不可修改，列表按 Playbook 内序号从新到旧排列。可以读取、比较、复制修订版本，也可以完整或部分恢复其内容。复制时明确选择目标项目及是否携带历史；此界面不复制发布记录。恢复会替换已保存的草稿内容，不创建修订版本。完整恢复会改变创作起点，部分恢复则保留原起点。

## 本地状态与冲突

每个编辑器独立保存 IndexedDB 备份，内容包括已保存基准和待保存操作。打开其他窗口不会覆盖这份备份。恢复时，将选定备份复制到当前编辑器；旧备份需要明确删除。备份失败时，内存中的修改会保留，页面会显示警告。浏览器存储用于辅助恢复，不代表内容已经保存到服务器。

保存会捕获当时的操作前缀，请求期间继续输入的内容在响应后仍标为待保存。保存失败后，先读取服务器，判断是否只是成功响应丢失，不自动重复写入。序号冲突时保留本地内容，提供比较和明确的放弃并重新载入操作。导航、文件选择和语言偏好与草稿内容分别保存。

提交修订版本、复制和恢复都针对已保存内容，执行前需先保存待处理修改。RPC 失败会显示错误，不自动重试。Playbook 不存在时，页面显示专门的缺失状态，并提供返回总览的入口。

## 接口与职责

[Host 适配器](src/index.ts)通过 DSH Connection 在 /api/papermoon 下注册精确的 POST 路由。已有传输层校验浏览器认证和 Host/Origin。请求保留 Connection 信封及关联 ID。[协议](src/protocol.ts)在分发前校验输入，[传输适配器](src/wire.ts)将业务 Map 转为无损 JSON，包括差异结果中的 Map。

| 操作组 | 接口 |
|---|---|
| 总览与项目 | catalog, projects, createProject, renameProject, deleteProject |
| Playbook | playbook, createPlaybook, renamePlaybook, deletePlaybook, copy |
| 内容 | snapshot, save, restore, compare |
| 修订版本 | commit, history, revision |
| 编译 | compile, compiled, revisionCompilation, revisionArtifact |

浏览器通过 DSH 插槽注册主页面和侧栏入口。[PaperMoon UI 库](../../packages/ui/README.zh.md)维护组件，页面代码不导入 DSH 的组件实现。与 DSH 的连接集中在薄适配器中，通过真实 Web 集成验证。普通组件和仓库测试无需 DSH checkout。

## 构建与验证

运行 pnpm build:plugins 生成 Host 模块和浏览器工厂。构建时复用宿主 React 模块，将 PaperMoon 样式放入延迟执行的工厂，不使用 DSH 私有构建工具。[根启动器](../../docs/development.zh.md)提供组合配置和数据位置。

运行 pnpm test:editor，以隔离的数据库、凭据目录和随机端口执行浏览器场景。测试创建并停止自己的 Web 进程，验证真实插件加载器与认证，不调用模型。主库检查分别覆盖接口和本地草稿状态。导航和编辑体验是否适合日常使用，仍由用户反馈判断。

## 编译与预览

草稿通过[编译服务](../playbook-compiler/README.zh.md)提供入口、语言和明确的编译操作。存在未保存修改时，需要选择保存后编译或取消。草稿预览读取已保存的检查产物。修订版本页只读取冻结附件，不提供编译操作；被引用产物缺失或损坏时显示持久数据错误。无产物版本提供恢复到草稿的入口，再次提交才能生成可演绎的新版本。

本地编辑、选项变化或服务器序号推进后，旧结果会标为过期。可见草稿页每五秒刷新一次，也在获得焦点或恢复连接时刷新，保留待保存修改。诊断跳转前再次核对服务器，再定位程序位置或文案键与语言；旧诊断不能选中新内容中的位置。预览不创建 Session 记录，也不代表已经获得发布资格。

开始演绎为最新版本或当前查看的历史版本打开[共用启动对话框](../performances/README.zh.md)。编辑器自身不运行模型，也不推断发布资格。
