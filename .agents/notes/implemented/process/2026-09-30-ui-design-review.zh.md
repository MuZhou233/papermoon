# Agent Note: 交付前的界面设计复审

Status: implemented

[English](2026-09-30-ui-design-review.md) | 中文

## 问题

界面通过行为检查后，仍可能有多余的导航步骤，或让主要操作淹没在次要信息中。交付流程需要明确时机，要求任务 Agent 按既有 UI/UX 原则重新评估设计。

## 决定

PaperMoon 的[交付流程](../../../../docs/testing.zh.md#交付流程)围绕本次需求，覆盖功能实现、检查、最终验收和交付。主库变更或 PaperMoon 携带的 DSH 补丁影响可见界面时，[交付技能](../../../skills/papermoon-checks/SKILL.md)在基础检查后、最终验收前触发一轮界面设计复审。复审以本次需求和既有设计原则为依据，产生的改动作为最终变更的一部分接受验证。

检出的 DSH UI/UX 指南提供设计和交互原则。PaperMoon 按[独立维护决定](2026-09-11-independent-maintenance.zh.md)维护执行时机和交付范围。现有检查为最终验收提供证据。流程与技能留在主库，主库文档检查继续独立运行。

## 考虑过的替代方案

仅在设计指南中补充原则，交付入口仍缺少明确的审视时机。独立审查任务可以带来另一种视角，也会增加协调成本，留作后续试验。另建截图套件会重复现有浏览器场景提供的证据，并增加维护工作。

## 影响

涉及 UI 的任务增加一轮设计复审，范围限定在本次需求和受影响界面。Agent 落实收益明确的改进，或说明保留合适方案的具体依据，再随实际验证结果报告判断。继续修改后，受影响的检查重新运行；内容保持原样时，已通过的结果继续有效。内部和纯文档任务从基础检查直接进入最终验收。设计质量仍依赖 Agent 的判断。
