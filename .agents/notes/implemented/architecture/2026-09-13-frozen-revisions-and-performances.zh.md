# Agent Note: 完整修订冻结与文本演绎

Status: implemented

[English](2026-09-13-frozen-revisions-and-performances.md) | 中文

## 问题

历史版本的可执行结果如果还能补充或替换，就无法作为权威记录。启动时重新编译，也可能因编译规则变化而改变行为。可变草稿检查服务于编辑，演绎则需要完整保留的输入。

## 决定

[提交服务](../../../../plugins/story-compiler/README.zh.md)先编译确定草稿，再执行一次 SQLite 修订事务。默认要求成功，只有明确允许时，剧本错误才可生成仅含源码的修订版本。多目标要么附带全部结果，要么全部不附带；操作故障始终中止。最终序号校验拒绝期间的编辑，不重新编译或重试。

存储负责通用不可变附件正文与有序清单。复制历史共享修订身份，删除最后一个目录引用时回收。核心不解释编译。独立产物读取器与运行时启动[演绎](../../../../plugins/performances/README.zh.md)，会话日志保存完整产物与来源。启动、恢复和 Fork 都不编译，源剧本删除不影响保留的会话。

本决定扩展 [CommonJS 决定](2026-09-13-commonjs-opening-compiler.zh.md)：独立文件产物用于草稿检查，修订附件保存权威历史。模块语法、冻结文本运行时和执行隔离继续适用。[人工编辑器](2026-09-12-manual-script-editor.zh.md)保留自由编辑草稿的能力，提交和历史预览遵循本决定。

## 考虑过的替代方案

附带用户选择的缓存 ID 会允许不编译待提交快照。启动时编译或提交后补充结果，会让历史行为依赖后来的可变状态。第二个编译数据库会拆开源码和产物的提交点。禁止编辑未完成草稿会妨碍正常创作，要求审批则引入无关流程策略。

## 影响

Story SQLite 格式 3 拒绝旧数据库，不改动旧文件。内容和产物格式保持不变。修订正文与附件原子提交，预览缓存可独立清理。编译失败只能通过明确允许的源码提交保留，这类版本不能开始演绎。源数据消失后，已初始化会话仍保留来源名称与完整产物。

确定性单元测试与真实 DSH 浏览器检查覆盖事务回滚、来源冲突、产物损坏、起始真实角色、仅开场展示、Fork 和来源删除。工程证据不替代用户对创作和叙事质量的反馈。
