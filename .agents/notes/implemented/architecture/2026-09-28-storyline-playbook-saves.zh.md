# Agent Note: Playbook 故事线存档

Status: implemented

[English](2026-09-28-storyline-playbook-saves.md) | 中文

## 问题

独立故事需要同时拥有创作内容与学习进度的存档身份。安装级尝试无法表示多份存档；单独持久化进度又会使章节完成依赖两份权威数据的协调。

## 决定

每份故事存档都是 Playbook，在草稿元数据中保存不可变故事线绑定与受保护进度。[共用需求](../../../../docs/story-mode/design.zh.md)维护行为，[雾锁地照](../../../../docs/story-mode/fogbound-earthshine/README.zh.md)从“第一个角色”开始。故事入口与普通列表共同展示存档。[创作决策](2026-09-29-plaintext-playbook-authoring.zh.md)提供统一授权，[引导决策](2026-09-29-story-mode-contextual-guidance.zh.md)提供上下文展示。这些决定保留[早期架构](2026-09-25-story-mode-layers.zh.md)的命名及向下依赖。

启动将已保存内容与编译产物冻结为普通无 tag 版本。受保护进度预留真实演绎 Session，使重试恢复同一次执行。模型选择与会话记录仍由所属模块保存。已持久化、完整成功且含模型正文的回合满足章节条件；预置开场、片段、仅思考输出及失败回合均排除在条件外。

存储支持从保留的启动版本提交。事务一起写入章节版本、Playbook／故事线／章节唯一 tag 及更新后的进度，保留较新的草稿值。重复完成或重试返回已有带 tag 结果。提交失败时章节保持未完成，重试复用已保存的成功回复。

章节附件冻结双语讲解与示例，并通过包含截止位置的记录边界引用成功世界线路径。回顾独立于执行读取这些值与有界日志，保留活动草稿、进度和演绎选择。记录缺失时明确显示状态。第一章保留继续对话，并展示第二章尚未开放。

## 考虑过的替代方案

独立故事文件或数据库会增加第二份权威数据。将完整会话记录或模型配置复制进 Playbook 会重复模块存储；引用保留职责，并将独立导出留给另行设计。完成时读取最新草稿会标记未经演绎的修改，恢复启动草稿又会丢弃后续创作。

原地重启与章节恢复会改动正在回顾的存档。独立新存档提供新的起点，只读回顾保留当前状态。交互重放需要另一份执行身份和模型请求，超出所选回顾行为。

从普通 Playbook 功能中隐藏故事存档会妨碍逐步教学，放开全部普通操作则可绕过阶段。共用策略按教学阶段开放功能。保留已废弃章节需求、代码或文案样本会继续维护过时行为；当前格式替换将历史交给 Git。

## 影响

Playbook 存储是进度与章节身份的唯一依据。策略缺失时暂停受保护操作。启动与章节提交使用不同的快照边界，同时保留演绎内容和未完成创作。沿用[当前格式政策](../../../../docs/development.zh.md#冻结修订数据)，现有运行文件保留原样。

存储测试验证事务回滚与唯一 tag 重试。故事测试覆盖独立存档、受控入口、重启恢复、并发完成及已保存成功回复后的重试。确定性浏览器章节验证实际请求顺序、后续草稿保留、有界回顾和刷新后的完成状态。包契约维护具体 API，需求继续维护准确的双语文案。
