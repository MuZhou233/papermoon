# Agent Note: 世界线导航与双模式轨迹

Status: implemented

[English](2026-09-18-dual-trajectory.md) | 中文

## 问题

一次玩家输入可能触发多次模型请求和工具步骤。按请求组织页面，容易让这些步骤看起来像不同的故事结果。按日志序号排序，还会改变 Playbook 指定的历史引用顺序。

## 决定

演绎使用一个轨迹页，包含世界线导航和完整 DSH 轨迹。节点保存一次接纳的输入及完整返回，包括工具过程和失败结果。楼层按祖先深度计算，DSH 轮次保留真实的发生顺序。查看位置、显示模式与运行位置分别维护。

原始模式读取截至所选节点的路径。改写模式只展示一次已保存的基础上下文，再展示该轮全部执行。上下文使用独立的展示身份，并保留来源入口，不创建日志事件、时间或用量。[模块文档](../../../../plugins/performances/README.zh.md#实际上下文)维护接口和导航规则。

DSH 扩展采用随 effect 生命周期清理的只读来源登记和导航槽位。Conversation 通过已有定义组装显式事件窗口。有序上下文保留原始消息身份和来源链接，与展示索引分开；执行记录保留轮次、步骤和请求分组。上下文引用不产生新的时间或用量。输入作者身份来自共用输入接纳流程保留的来源元数据，不由检查提供者覆盖。

## 考虑过的替代方案

伪造序号或时间戳会模糊来源身份。修改当前 Conversation 绑定，会把检查与 Chat 和执行耦合。独立渲染器还会丢失共用的附件处理和展示策略。

分别保留世界线页和请求页，需要用户在两套导航间往返。用文本预览替代 DSH 轨迹，会丢失工具、思考和请求检查。按来源序号排列拼装引用，会改变 Playbook 指定的顺序。为了查看历史而切换运行位置，可能改变下一次生成的结果。

## 影响

清理登记后恢复普通来源。提供者负责选择语义、翻译标签和不可变请求读取，共用轨迹保留搜索、折叠、详情和复制行为。扩展不改变 Session 事件或 SDK 格式。测试覆盖引用重排、普通视图、构建产物和 effect 清理。

整轮检查复用已保存的拼装和世界线记录，不改变数据格式。分页绑定快照，拒绝混用游标；执行归属不明确时直接报错。历史上下文不产生新的耗时或用量。输入按持久记录中的消息来源分类。重 roll 和编辑重发使用[共用的用户输入接纳流程](2026-09-18-user-input-reexecution.zh.md)。选中节点只改变行样式，不压缩文字高度；导航过渡遵循减少动态效果设置。对话展示交流内容和回复操作，轨迹负责拼装上下文检查，避免在消息之间再放一套上下文查看器。主库测试负责楼层及导航，DSH 通用检查注册和轨迹扩展采用选定的补丁检查要求。

本决定细化[世界线](2026-09-16-worldlines.zh.md)与[请求拼装](2026-09-17-context-composition.zh.md)的检查方式，保留其执行、持久化和状态规则。
