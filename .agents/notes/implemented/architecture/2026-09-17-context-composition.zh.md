# Agent Note: 剧本决定请求上下文

Status: implemented

[English](2026-09-17-context-composition.md) | 中文

## 问题

完整世界线记录经历，模型请求却可能只需要部分历史，以及插入其中的提示词。若两者共用一份只追加的消息列表，剧本就无法定义历史窗口，改变请求也会混同于改变历史。

## 决定

冻结剧本提供同步的 composeContext 函数。每次接纳输入时，以父节点只读状态和历史身份求值一次。宿主展开选中的原文块，确认保存后发送；工具续接复用这份基础上下文。原始回复及完整工具交互不可拆分。实际请求检查只读取持久引用和自定义正文，不重新执行脚本。[API 文档](../../../../plugins/story-compiler/api.zh.md#上下文拼装)负责详细接口约定。

该机制扩展[世界线决定](2026-09-16-worldlines.zh.md)，不改变节点和选择规则。产物与演绎初始化要求第三版格式，旧数据保留但不受支持，使用拼装需重新提交源码。数据库和业务内容格式不变。

## 考虑过的替代方案

用历史选择表达窗口会让记录从对话和轨迹中消失。每次工具调用后重新拼装会移动尾部提示，破坏同轮稳定前缀。将完整历史正文传入 Worker，会让小窗口也承担被丢弃正文的处理成本。独立的运行期预设会让剧本无法完整决定自己的上下文。

## 影响

剧本可以在原文引用前后插入普通 user 和 assistant 提示词，并指定完整系统头部。它不能加工历史正文、伪造工具结果或读取其他路径。无效拼装会停止请求，保存无法确认时阻止继续执行。重 roll、分支和恢复后，历史请求仍保留原始消息。摘要和记忆生成不属于本机制。
