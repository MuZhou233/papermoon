# Agent Note: Playbook 决定请求上下文

Status: implemented

[English](2026-09-17-context-composition.md) | 中文

## 问题

完整世界线记录经历，模型请求却可能只需要部分历史，以及插入其中的提示词。若两者共用一份只追加的消息列表，Playbook 就无法定义历史窗口，改变请求也会混同于改变历史。

## 决定

冻结 Playbook 提供同步的 composeContext 函数。每次接纳输入时，以父节点只读状态和历史身份求值一次。宿主展开选中的原文块，确认保存后发送；工具续接复用这份基础上下文。原始回复及完整工具交互不可拆分。实际请求检查只读取持久引用和自定义正文，不重新执行脚本。[API 文档](../../../../plugins/playbook-compiler/api.zh.md#上下文拼装)负责详细接口约定。

该机制扩展[世界线决定](2026-09-16-worldlines.zh.md)，不改变节点和选择规则。[Playbook 命名决定](2026-09-24-playbook-and-story-mode.zh.md)现已规定不兼容的命名和格式边界。拼装继续使用冻结产物，不迁移旧记录。

DSH 通过必读的 request/messages 事件保存有序的原始事件引用和生产者内联消息，可以扩展更早的请求。请求消息瀑布在输入接纳和请求头记录后运行，提供者确认持久化后才返回记录序号。Loop 和重建不变量共用 Session 解析器。普通消费者仍从选中历史派生消息。消费者负责基础请求的分组与保留策略，完整消息和工具的估算独立于累计用量。Chat 可以打开具名检查视图，无需选择执行历史。

## 考虑过的替代方案

拦截流式请求参数会绕过持久重建。永久注入消息会把单次请求输入混入对话事实。每次请求都复制展开后的全部历史消息，会重复不可变内容。另建日志会拆开请求依据与所属 Session。

用历史选择表达窗口会让记录从对话和轨迹中消失。每次工具调用后重新拼装会移动尾部提示，破坏同轮稳定前缀。将完整历史正文传入 Worker，会让小窗口也承担被丢弃正文的处理成本。独立的运行期预设会让 Playbook 无法完整决定自己的上下文。

## 影响

引用必须早于所属记录，并指向消息事件。后续历史选择不能改写已保存的请求。必读事件不改变 Session 结构版本，也不修改发布版校验器。Session、Loop 和 scope 测试覆盖解析与分发，录制的 request-context 回放验证普通视图和 SDK 投影。

Playbook 可以在原文引用前后插入普通 user 和 assistant 提示词，并指定完整系统头部。它不能加工历史正文、伪造工具结果或读取其他路径。无效拼装会停止请求，保存无法确认时阻止继续执行。重 roll、分支和恢复后，历史请求仍保留原始消息。摘要和记忆生成不属于本机制。
