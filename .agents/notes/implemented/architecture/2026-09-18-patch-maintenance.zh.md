# Agent Note: DSH 补丁维护

Status: implemented

[English](2026-09-18-patch-maintenance.md) | 中文

## 问题

按实现先后追加的补丁反复修改同一批 DSH 文件，也把共享机制与插件修改混在一起。机械地按包分组会拆散小型消费者适配，同时保留 DSH 全站文档与决定记录流程。两者都增加了理解和维护局部修补的成本。PaperMoon 仍以产品插件集合为主体，保留必要的上游修补。

## 决定

按当前职责维护相对官方固定基线的最终差异。每个受修改文件只归属一份补丁，相关实现、测试和直接契约可以跨越包边界。补丁名称和目录层级可以随内容调整。[补丁指南](../../../../patches/README.zh.md)维护长期编辑、重组和插件提升规则，清单维护当前文件列表与检查。

当前组织方式围绕以下共同维护需求，不构成永久分类：

| 补丁 | 职责 |
|---|---|
| `shared/build.patch` | 正常构建所需的已知输出清理 |
| `shared/session.patch` | Session 记录、恢复、历史与请求选择，以及依赖它们的读取器和查询适配 |
| `shared/tools.patch` | 工具 schema、校验与语言类型渲染 |
| `shared/runtime-catalogs.patch` | 由多项职责共同派生的运行时 API、槽位和作用域事件 |
| `plugins/agent-loop.patch` | 请求执行和工具参数诊断 |
| `plugins/session-controller.patch` | 输入接纳、宿主提交、客户端读取与列表展示 |
| `plugins/workspace.patch` | 资源工作区及协作控制器、客户端导航和预设选择 |
| `plugins/chat.patch` | Chat 内容与回复展示 |
| `plugins/conversation.patch` | 对话组装与输入扩展 |
| `plugins/trajectory.patch` | 只读轨迹检查 |
| `plugins/token-meter.patch` | 完整请求的 token 估算 |

PaperMoon 保留 DSH 的代码和运行时约束、直接双语包契约、运行时生成产物及行为证据。发行版携带的补丁不承担全站文档和 DSH Note 同步。补丁理由归入主库所属决定。本范围细化了[独立维护](../process/2026-09-11-independent-maintenance.zh.md)中的补丁部分，主仓库独立维护的决定不变。

现有插件修改继续保留为补丁。它们提供通用的组装、展示、检查和资源能力，PaperMoon 已经负责自己的产品策略。复制完整插件会接管仍值得跟随的上游行为。是否提升为插件，仍按职责和维护收益单独判断。

## 考虑过的替代方案

按时间排列的补丁栈保留中间状态和应用依赖。严格按包分组，会拆散只为配合另一项修改而存在的适配。单个总差异难以辨认职责。固定目录或逐文件归属登记表，会为普通重组增加第二份映射。

沿用 DSH 完整文档流程，会让局部代码修补同时更新全站参考、翻译和重复决定记录。删除全部文档会丢失调用处的契约；删除全部生成产物会移除插件实际读取的代码。保留包契约和运行时目录，覆盖这些实际用途。

派生仓库或文件覆盖会复制更大的上游范围。Git 和源码比较已能支持所选表示方式，新增导出工具会多出一项维护接口。初始化时自动生成会增加第二个重建阶段；运行时生成差异继续保存为补丁。

## 影响

最初重组保留了上游 Gitlink、运行时行为、既有测试和快照。后续 [rc.2 迁移](2026-09-25-dsh-rc2-migration.zh.md)更新基线及其消费者。全站文档恢复上游基线。补丁中的独有理由整合进主库所属 Note，工具参数错误另保留一份 bug-fix Note。直接包契约保留语义和双语记录。

补丁读取器拒绝重复文件归属，包括重命名前的路径。重建和源码比较仍与交付检查分开。运行时目录检查替代全站文档汇总，行为测试、录制回放、类型检查和 lint 继续登记。Host 生成器的运行时专用模式采用同一投影，不生成或检查文档；默认模式不变。

单纯重组采用源码等价验证，不新增 Note，也不重跑未改变行为的检查。功能提升、归属义务变化或行为变化仍需更新所属决定和相关证据。[子模块决定](2026-09-11-submodule-launch.zh.md)继续维护固定基线重建和运行数据隔离的依据。
