# Agent Note: 固定子模块与原版启动器

Status: implemented

[English](2026-09-11-submodule-launch.md) | 中文

## 问题

可复现的应用基线需要与独立维护的产品插件共存，并在源码重建时保留用户运行数据。

## 决定

父仓库 Gitlink 固定官方 DSH。有序补丁重建受管源码，初始清单为空。原版构建后的 Web CLI 以父仓库为工作目录，使用独立的默认数据目录。自动依赖安装与构建使用已支持的 CI 安装路径，避免在子模块中配置开发 hook。

## 考虑过的替代方案

将产品代码放在框架树中会混合归属和交付义务。独立实现另一套应用启动会重复 DSH 行为。默认把工作区设为子模块会将用户工作放入可重置的 checkout。

## 影响

升级显式更新 Gitlink 与补丁证据。初始化丢弃未导出的受管源码变更，保留已忽略配置和父仓库数据。构建与启动分离。主库与子模块检查各自独立，补丁可应用本身不是交付证据。
