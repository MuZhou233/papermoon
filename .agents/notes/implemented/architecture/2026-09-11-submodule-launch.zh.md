# Agent Note: 固定子模块与原版启动器

Status: implemented

[English](2026-09-11-submodule-launch.md) | 中文

## 问题

PaperMoon 需要能够重建应用源码，并独立维护产品插件。重建源码时必须保留用户运行数据。

## 决定

主仓库的 Gitlink 固定 DSH 官方版本，工具按顺序应用补丁来重建源码，初始补丁清单为空。启动器运行原版 DSH 构建后的 Web CLI，以主仓库为工作目录，使用独立的默认数据目录。安装依赖和构建时使用 DSH 支持的 CI 安装方式，避免在子模块中配置开发 hook。

## 考虑过的替代方案

将产品代码放进 DSH 源码目录，会混淆两者的维护职责和交付要求。另写一套应用启动逻辑，会重复 DSH 已有的功能。把子模块设为默认工作区，则会把用户文件放入初始化时会重置的目录。

## 影响

升级时需要更新 Gitlink，并重新验证补丁。初始化丢弃子模块中尚未导出为补丁的源码修改，保留 Git 已忽略的配置和主仓库数据。构建与启动分别执行。主仓库与子模块按各自规则检查，补丁成功应用后仍需验证。

[人工编辑器决定](2026-09-12-manual-script-editor.zh.md)在根启动入口增加产品组合配置，同时保留原版 Web 命令；本文的子模块和进程归属决定继续适用。

DSH 检查保留 setup 的 CI 包管理器环境，主库在交互环境运行时，子模块仍使用相同的依赖布局。
