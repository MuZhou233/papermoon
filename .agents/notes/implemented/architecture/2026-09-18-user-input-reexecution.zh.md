# Agent Note: 世界线中的用户重新提交

Status: implemented

[English](2026-09-18-user-input-reexecution.md) | 中文

## 问题

重 roll 和编辑重发都表达了用户再次生成回复的意图。插件来源记录遮蔽了这一作者身份，需要分别修补对话、轨迹和输入摘要。

## 决定

[演绎插件](../../../../plugins/performances/README.zh.md#世界线)通过共用的 Host 接纳流程，将这些操作作为新的用户输入提交。世界线记录保留 rerollOf 或 editedFrom，新消息不继承旧请求身份或上传凭据。校验通过后，父节点选择与输入接纳合为一次持久操作。

中断输入保留用户来源，不补造模型轮次。既有节点与日志保持原样；从旧节点发起的新执行采用当前提交语义。[世界线职责](2026-09-16-worldlines.zh.md)及其不可变状态模型继续生效。

DSH Session Controller 为线协议提示词和可信宿主提交共用输入接纳流程。保留的附件只检查可用性，不消耗上传回执。全部校验监听器完成后，串行接纳事件才持久保存消费者记录，之后才入队。轮次之外保留的用户输入保持原来源，不伪造执行坐标。Chat 和轨迹直接读取来源，不使用生产者允许名单或身份覆盖；重执行来源单独保留。

## 考虑过的替代方案

直接进入 Agent 队列会跳过模型、附件和输入接纳检查。复用旧请求身份会混淆新执行与传输重试。展示覆盖和生产者允许名单只能修正个别视图，其他消费者仍可能采用不同的作者分类。

保留插件来源再增加展示例外，会要求每个新的历史消费者识别重复的用户输入。只修改消息标签而不共用接纳流程，则会让校验行为继续取决于用户点击了哪个入口。

## 影响

校验失败阻止接纳，但持久接纳后的失败不撤销先前写入。普通模型重试和插件编写上下文保留各自身份。共用测试覆盖校验顺序和晚期拒绝、持久附件、新身份、中断和对话排序，已有日志不改写。

普通发送、重 roll 和编辑重发共用输入处理，由选中的父节点和来源记录区分。操作重试不会变成另一个用户轮次。显式装配的输入处理插件会处理新的提交，模型自动重试则保留已经拼装的上下文。测试比较实际请求，并验证状态、身份、中断和展示覆盖的移除。
