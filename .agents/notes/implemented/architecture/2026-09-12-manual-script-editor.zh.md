# Agent Note: 通过产品 UI 与宿主适配器支持人工创作

Status: implemented

[English](2026-09-12-manual-script-editor.md) | 中文

## 问题

创作内容需要人工界面，支持程序与多语言文案编辑、提交及历史查看。如果页面直接引用 DSH 组件源码，产品修改就会依赖受管 checkout。如果把编辑缓冲区当成已持久化内容，也会混淆冲突与保存成功的状态。

## 决定

[编辑器插件](../../../../plugins/story-editor/README.zh.md)维护浏览器页面，并通过 DSH 认证传输发送经过校验的请求。薄适配器负责注册插槽和精确请求路由。DSH 的主页面与侧栏扩展点已能支撑这些页面，无需源码补丁。[UI 库](../../../../packages/ui/README.zh.md)维护注明来源的组件副本及 CodeMirror 绑定，DSH 提供主题变量和共享 React 运行时。

总览直接展示剧本，项目用于分组和筛选。详情页分别提供可编辑草稿、不可变修订版本和管理设置。保存、提交与恢复仍是逻辑核心上的明确操作。此界面不提供编译、发布、审核或模型流程，也不编辑元数据。

本地编辑器保存已持久化快照和有序的待保存操作。保存使用读取时的序号，并保留请求期间继续输入的内容。独立的 IndexedDB 备份避免一个窗口覆盖另一个窗口的恢复数据。冲突时保留本地内容，供用户比较和明确处理。存储层仍是权威来源，备份和导航记录不成为业务实体。

## 考虑过的替代方案

直接导入或转导出 DSH 组件，会让两个仓库共同承受实现变化。注明来源的副本增加了维护工作，但产品 UI 可以独立修改。替换 DSH 外壳则会重复实现插件已经可以复用的导航、主题和认证。通用编辑器后端注册表会在第二种编辑器出现之前增加抽象。

Monaco 提供更完整的代码开发环境和语言服务。CodeMirror 可以按扩展组合当前需要的编辑、只读和比较功能，译文则继续使用普通多行控件。以后可以接入编译器及诊断，无需让编辑器承担源码持久化职责。

真实集成中，独立的 Connection RPC 通道注册访问了提供方注入范围之外的 Host 服务，导致加载失败。使用现有认证传输的精确路由，可以避开这个调用路径，无需修改 DSH 或绕过认证。路由和请求校验都保留在适配器中。

## 影响

根启动入口在标准 Web profile 上组合 PaperMoon，同时保留单独的原版 Web 命令用于对照。补丁清单仍为空。总览筛选和历史倒序查询扩展了通用仓库 API，不改变数据库或业务内容格式。[核心设计决定](2026-09-12-script-core.zh.md)继续规定创作内容结构和修订版本语义。

主库测试无需 DSH，分别验证本地编辑状态和请求行为。浏览器集成使用临时数据、真实插件加载器与认证路由，结束后停止自己的进程。工程检查与用户体验反馈仍分别记录。
