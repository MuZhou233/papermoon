# Agent Note: 快照事务上的对象编辑校验

Status: implemented

[English](2026-09-13-object-scoped-edits.md) | 中文

## 问题

程序与文案工具共用一份可变草稿。要求模型提供整份序号，会让无关修改使另一个待执行操作失效。同一文案的不同语言也保存在同一个 KV 值中，仅按数据库键校验仍会拒绝本可并行推进的编辑。

## 决定

[局部工具](../../../../plugins/story-tools/README.zh.md#会话读取记录)将受影响对象与会话原有读取记录比较，再在最新完整快照上应用操作。逻辑核心校验最终结构，现有存储事务检查快照序号后保存 KV 变化。序号校验拒绝时，按相同意图与读取依据重新计算，最多尝试三次。这部分替代[编剧会话设计](2026-09-12-writer-sessions.zh.md)中由模型提供编辑序号的做法，会话归属与读取记录的生命周期保持不变。

数据库保存权威内容，候选内容只有在事务提交后才获得持久身份。回执和读取记录使用该次提交的快照，即使另一个写入者已经推进草稿。平台内部读取不授予其他对象的修改权限。已读译文被删除后会产生冲突，重新读取并确认缺失后才允许重建。默认语言使用独立的读取值校验。

提交和恢复保留明确的整份草稿序号校验。删除语言会影响该语言的全部译文，因此操作自身携带序号。事务中不调用模型、不编译，也不执行外部 I/O。只有序号校验拒绝才重算，数据库占用、其他失败和已经提交的操作均不重试。

## 考虑过的替代方案

移除存储序号校验会让旧候选内容覆盖新数据。只替换预期序号而不重新计算也有同样的问题。按 KV 条件写入仍会把译文和共用设置绑在一起，将业务字段校验放入 SQL 则会使存储模块依赖创作规则。跨业务回调持有写事务会延长锁定时间，也会改变存储接口。剧本独占绑定会阻止预期的共同编辑流程。

## 影响

局部工具调用不再接受批次级 expectedSequence。现有人工编辑器调用与存储 API 保留各自的序号语义，无需改变数据库格式或 DSH 补丁。内存读取记录仍可丢弃，恢复或重新挂载后通过明确读取重新建立。

测试使用不同 SQLite 连接，在计算与持久化之间插入竞争写入，覆盖独立文件与译文、同对象拒绝、回滚、有限重试、取消和较早提交快照的回执。真实 DSH 检查覆盖独立工具 scope，以及同一模型响应中的两次独立编辑调用。工具不会自动合并同一已读对象上的竞争修改，也不会因提交后回执丢失而重放调用。
