# Agent Note: 纯文本创作与按范围开放编剧工具

Status: implemented

[English](2026-09-29-plaintext-playbook-authoring.md) | 中文

## 问题

第一个角色需要直接编辑系统与开场。仅有程序的模型会让这些操作依赖脚本结构，未受限的编剧工具与历史则可在教学开放前读取或改变内容。

## 决定

[创作需求](../../../../docs/playbook-authoring.zh.md)通过独立的系统与开场模式实现。普通 Playbook 默认使用纯文本，切换后保留未选中模式的内容。有序消息具有稳定身份，保存角色与正文原文。共用 CodeMirror 控件提供显式 Markdown／XML 高亮、查找、撤销和保存状态；语言配置隔间切换高亮时保留文档、光标及历史。

手动界面将展示设置放入与编辑框相连的工具栏，每条开场消息使用带序号的卡片。紧凑菜单复用共用 DSH 选择与焦点行为，局部样式统一行号、间距、操作图标及编辑框。编辑器与提示词轨迹共用采用轨迹表格配色的角色标签组件，保持角色颜色一致。菜单使用不透明的第二层背景，使选项与下方文本清楚分开。设置与内容的关系更清楚，创作生命周期保持原有规则。通过 Portal 渲染的菜单先完成测量定位，再将焦点移入选项；后续滚动或尺寸变化引起的定位保留该焦点。

共用编辑器样式同时覆盖原生光标、原生选区与 CodeMirror 绘制层。语法高亮使用 DSH 代码块配色，查找控件和版本差异使用其背景与状态颜色。CSS 响应主题变化，编辑器保持当前状态，因此切换主题时可保留编辑实例，也能跟随应用中明确选择的主题。

纯文本直接准备冻结上下文。混合模式使用脚本编译，仅替换选为纯文本的部分，冻结的 `sourceContext` 将脚本校验与替换结果分开。函数、状态和自定义拼装延续现有模块职责。首次演绎冻结已保存内容，章节提交按[存档决策](2026-09-28-storyline-playbook-saves.zh.md)复用该来源。

核心能力解析、授权与裁剪服务于人工编辑、编剧工具、版本及演绎，故事模式提供注册策略。系统、开场、程序、文案、历史和编译工具分为独立模块，目录筛选、帮助主题、结果裁剪与执行共用能力范围。策略缺失时暂停受保护操作。元数据、恢复、复制及其他入口同样检查权限。

阶段变化刷新已有编剧会话的注册，恢复与 Fork 后解析当前权限，每次调用再次检查范围。对象读取保护与原子序号写入保留[编辑决策](2026-09-13-object-scoped-edits.zh.md)。人工保存保留请求期间继续输入的内容，并通过系统／开场比较呈现冲突。编剧权限排除绑定、进度及章节 tag 写入。

章节能力遵循[五节表](../../../../docs/story-mode/fogbound-earthshine/01/README.zh.md)：先开放开场，再开放系统、模型选择与演绎。编剧保存满足相同内容条件，包括空开场。前几节继续推进仍由用户明确操作，教学文本直接采用需求原文。

## 考虑过的替代方案

在简化编辑器背后生成脚本会使纯文本创作依赖脚本结构，整个 Playbook 共用一种模式又会限制混合使用。独立的正式内容类型直接表达每种选择，普通模式切换时保留创作。

仅在 UI 筛选或会话创建时注册工具，会让直接与旧调用绕过策略。只限制写入又会通过读取暴露未开放内容。统一授权覆盖发现与执行，同时维持可复用工具对章节的独立性。

编剧修改后再强制人工保存，衡量的是使用了哪个入口，而非内容是否保存。强制设置消息会排除玩家主动开场，自动填入示例会代替用户最初的创作选择。旧文案样本会保留已删除设计。空白初始内容与当前需求检查维护所选行为。

## 影响

普通创作获得直接编辑路径，脚本创作仍可独立选择。当前格式内容与冻结产物一起调整，现有数据保持原样。[引导决策](2026-09-29-story-mode-contextual-guidance.zh.md)跟随这些能力，授权仍由核心负责。

单元与集成检查覆盖原文保留、混合拼装、部分读取保护、策略卸载、旧调用、已有会话更新及 Fork。CodeMirror 测试验证高亮切换后的正文、选区与撤销。编辑器与编剧浏览器套件验证普通创作、编译、冲突和对话，第一章浏览器检查实际发送到确定性模型的系统原文与有序消息。
