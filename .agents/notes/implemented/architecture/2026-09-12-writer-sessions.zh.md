# Agent Note: 编剧会话与读取保护

Status: implemented

[English](2026-09-12-writer-sessions.md) | 中文

## 问题

编剧配置需要进入可恢复、可审查的对话。多个 Agent 和人工编辑可以共享 Playbook。按目录识别工作区、共享读取权限，都不能表达这种归属关系。

## 决定

[会话插件](../../../../plugins/writer-sessions/README.zh.md)维护 Playbook 目标、准备状态和接纳时固定配置。已接纳输入保存完整编剧快照，预置消息保留真实角色和稳定身份。运行期读取记录校验已返回对象的内容，存储与逻辑核心不承担会话策略。[按对象校验编辑的决定](2026-09-13-object-scoped-edits.zh.md)规定局部冲突的处理方式，序号校验保留在持久化过程中。

DSH 工作区扩展为资源提供独立于进程 cwd 的稳定目标身份。提供者解析目标并校验持久成员关系；目录目标保留规范路径校验，旧登记格式会被拒绝。创建和输入接纳钩子先于接纳完成；预设选择在重组前校验，在持久选择后协调关联，并受空闲互斥约束。

编写的用户与助手上下文保留生产者元数据和消息身份，不伪造模型请求。它在系统消息之后、已接纳输入之前提交。普通注入上下文仍是独立的用户消息，标明生产者，进入收件箱即持久保存，接纳时原样记录，不附带提示词前缀或请求封套。Chat 可以独立于过程折叠保留编写的节点。

## 考虑过的替代方案

把资源当作目录会让分组依赖文件系统访问。伪造助手请求会扭曲用量和请求重建；把所有编写角色包装成用户消息会改变模型语义。始终解析最新配置会丢失历史来源。插件自带循环则会重复队列、取消和持久化行为。

虚拟 Playbook 目录会混淆资源身份与进程 cwd。拼接起始消息会丢失角色；每次请求读取最新配置会改变历史上下文。独占绑定会阻止人工与多会话编辑。持久保存读取权限，会让恢复后的 Agent 获得当前读取生命周期之外的内容修改权。

## 影响

共用钩子不包含 PaperMoon 数据策略。删除资源只影响可用性，不改变已保留的对话身份；普通目录导航仍受支持。必读的上下文事件会拒绝不认识它们的读取器。当前事件先经过校验，再交给已冻结的发布版关系检查器：内部用户角色视图只为后者保留坐标，不持久保存，也不返回。恢复后保留原始角色和接纳元数据；角色、元数据或展示引用无效时，在使用内部视图前失败。针对工作区、输入接纳、Session 和回放的测试覆盖这些共用约束。

Playbook 和编剧数据库格式不变，通用工作区与消息能力通过 DSH 补丁维护。恢复、Fork 和插件重挂载建立新的工具作用域，要求重新读取。配置快照增加日志大小，但编剧配置变更或删除后，仍可审查原请求。
