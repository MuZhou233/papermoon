# Agent Note: 创作内容核心与持久化适配

Status: implemented

[English](2026-09-12-script-core.md) | 中文

## 问题

程序和多语言文案编辑需要共用规则，供未来的模型工具和用户界面调用。将这些约定直接写入 SQL，会让频繁的创作功能调整影响持久化模块。分别写在工具或编辑器中，又会重复校验，并让同一修订版本出现不同解释。

## 决定

[逻辑核心](../../../../plugins/story-core/README.zh.md)定义只读创作内容快照、纯操作和带版本的业务 KV 编码。独立仓库入口将这些规则与[存储 API](../../../../plugins/story-storage/README.zh.md)组合，薄 Cordis 使用者注册仓库服务。纯入口不加载 Node 内置模块或 Cordis；仓库不拥有连接，也不维护权威内存缓存。编译器及面向模型和用户的接口各自作为使用者，发布登记不内置审核或编译前置条件。

程序使用虚拟文件，文案条目保存用途说明和精确语言译文。每个创作内容实体都有随正文保存的 JSON 对象元数据。管理元数据留在项目、剧本或草稿上，修订版本与目录项元数据则是提交时显式给出的不可变资料。译文查询明确报告缺失，不做键级回退，让调用方看见翻译缺口，避免悄悄混用语言。草稿和修订版本均允许源码未写完或翻译不完整。

内容头占一条 KV 记录，文件、已登记语言和文案条目各占一条记录，译文保留在所属条目的 JSON 值中。核心维护这些键约定、格式校验和分组业务差异。SQL 过滤相等值并分页返回变化记录，核心不会仅为比较而读取全部正文。文本行对齐由展示层负责。

业务编辑先在内存中校验候选内容，再通过序号校验事务保存变化条目。写入失败时，不将候选结果报告为已保存。完整恢复改变草稿创作起点，部分恢复只编辑所选内容，不声称整份文档有了新来源。[存储归属决策](2026-09-12-script-storage.zh.md)继续规定共享修订版本和引用回收。存储只增加实体元数据、原子初始内容和实体属性与内容快照读取，不解释业务记录。

## 考虑过的替代方案

让实体方法隐含数据库读写，会模糊候选修改与已提交结果的区别。长期维护内存镜像则需要另一套并发与同步机制。显式快照和小型持久化适配器保留当前数据库的权威地位。

为每项职责建立抽象仓库注册表或独立包，会在没有独立实现时增加接口。纯入口、仓库入口和插件入口区分了导入依赖与生命周期，同时将内聚的功能留在一个包中。共享身份类型和纯 JSON 编码器复用已有存储词汇，不将数据库实现带入纯入口。

允许文案自由嵌入源码，会让程序与文案编辑缺少共用数据接口。强制每个程序字符串都引用文案键，又会引入源码分析并限制剧本语言。显式文案目录提供针对性的文案操作，源码校验和创作指导仍由所属模块负责。

键级回退可能返回看似完整、实际混合多种语言的内容。精确语言读取让缺失可见，上层仍可为一次完整操作选择一种语言。将整个目录存为一个 KV 值虽然便于编码，但小幅文案修改也要重写全部条目。每条文案一行，可以将译文与元数据保存在一起，无需引入特定语言的 SQL 结构。

## 影响

新剧本在没有源码时就具备合法内容结构。业务提交修订版本要求说明非空白，通用存储 API 仍允许更宽泛的文本。元数据和实体属性由各自模块文档说明；核心不包含会话占用、文件读取记录、审核状态或编译产物。

数据库格式为 3，拒绝版本 1 和 2 文件，不迁移或删除。业务内容使用独立的 papermoon.story 版本 1 身份，后续值格式变化不必修改 SQL 表。测试覆盖纯内容、仓库事务、构建后的纯导入和真实 Cordis 依赖清理。[人工编辑器](2026-09-12-manual-script-editor.zh.md)通过产品配置挂载本服务，原版 Web 与 DSH 源码保持不变。
