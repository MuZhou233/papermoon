# Agent Note: DSH rc.2 迁移

Status: implemented

[English](2026-09-25-dsh-rc2-migration.md) | 中文

## 问题

PaperMoon 的补丁原本基于较早的 DSH 提交。rc.2 更换了预设发现机制、Session 消息结构和客户端绑定生命周期。继续保留旧接口会重复承担上游职责，并使同时打开的会话相互耦合。

## 决定

将 `dsh-v0.1.7-rc.2` 固定到 `477b4f420553e8a52c2fbccc464d7561b239c443`，保持 Node 24 和 pnpm 11.7.0。尽量缩小补丁范围；缺少必要的通用能力时允许扩大。产品策略留在 PaperMoon 插件中。完整沿用上游“编码工具”开关，不增加显示例外，关闭后也不改变已有会话的模式。

Profile 通过 registry 声明编剧和演绎预设。选择钩子在 Agent 维护保护内串行执行，产品校验和工作区协调完成后才接纳输入。初始化监听器在可等待的 Agent 创建事件中完成，不等待该 Agent 自身进入空闲。

采用 Session v4 的 developer 消息和独立工具结果，移除对旧消息结构的假设。预置 assistant 上下文明确记录生产者；适配器以不依赖供应商的表示保留其角色，不伪造模型来源。请求重建使用对应历史位置的投影，也覆盖续接请求的基础记录。历史选择同时重建消息投影与工具声明。拼装校验和针对不可变的源消息计算，投影后的内容仍可作为合法请求输入。

预设选择仍由上游控件负责。产品侧仅通过最小的按绑定读取接口，获取新会话的待选状态或已有会话的预设投影。编剧、演绎、检查状态及订阅归各自 Session 绑定所有，插件卸载时也会释放。输入阻塞保留独立来源，并支持允许编辑但禁止发送。资源工作区保留上游归档、置顶、活动处理和导航行为。

这些要求需要扩展少数此前未修改的消费者：模型适配转换需要支持不依赖供应商的预置消息，新对话组装需要产品插槽，挂载的编辑器需要在阻塞时继续显示草稿。针对性回归覆盖这些消费者。单独的构建补丁将新增的桌面键盘类型输出目录加入上游清理白名单，否则正常父仓库构建会在清理阶段终止。对应回归确认相邻文件不受影响。这些缺口属于通用运行时和构建机制，不需要复制完整上游插件。

移除旧预设目录扫描和全局选择状态，保留上游 Agent 创建、普通输入接纳与“编码工具”展示行为。现有产品仍需要上下文、历史、包含式联合 schema、原生工具呈现、回复保留和轨迹扩展。运行时 catalog 与直接双语契约随最终实现更新。[补丁维护决策](2026-09-18-patch-maintenance.zh.md)负责组织方式，[补丁指南](../../../../patches/README.zh.md)维护范围原则。

## 考虑过的替代方案

保留旧预设发现机制和全局客户端状态会延续过时接口，无法正确支持多会话。替换完整上游插件会扩大维护范围。删除通用上下文和历史钩子会丢失现有 Playbook 与世界线功能。这些方案均不能满足迁移目标。

忽略清理失败或复制源码另行构建会绕过正常重建路径。修正缺失的精确输出分类，能让 setup 和 build 在实际托管检出中工作，也能独立验证这项修补。

## 影响

父仓库 Gitlink 和完整补丁集必须一起更新，因为 setup 读取暂存 Gitlink 并重置 DSH。验证先重建补丁，再在实际托管检出中构建、测试。临时检出仅用于源码比较。登记检查覆盖运行时 catalog、受影响行为、确定性回放、类型与 lint；产品集成和浏览器测试另行覆盖用户链路。审阅双语文本后再更新配对记录，不增加 DSH 全站检查。

当前测试录制采用 DSH 格式常量和当前消息结构，继续排除产品数据迁移、历史别名及格式演进测试。DSH 仍负责自身协议版本和恢复机制。该次迁移未修改故事模式及当时的 DeepSeek API Key 小节占位文档。当前的[第零章需求](../../../../docs/story-mode/00/README.zh.md)另行维护。
