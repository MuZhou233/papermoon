# Agent Note: 故事模式分层与第零章

Status: implemented

[English](2026-09-25-story-mode-layers.md) | 中文

## 问题

章节驱动开发必须引导用户操作真实产品，不能把通用运行机制不断塞进章节插件。第零章还需要一个固定示例，使用与真实对话相同的轨迹交互，同时不进入真实练习历史。

## 决定

采用平台层、扩展层和故事模式层三个职责层。所有 DSH patch 都属于平台层；扩展层以插件承载可复用的功能，故事模式层只承载章节内容和专属体验规则。依赖向下，不移动现有目录。[架构文档](../../../../docs/architecture.zh.md)维护当前职责图。

文本对话扩展使用完整的原样提示词、不继承运行时上下文、不带工具，组合出 DSH Agent，并提供模型元数据、选择、持久请求检查，不提供客户端页面。作为消费者的故事模式插件持有 Agent 生命周期，负责进度和步骤条件。没有工作区根目录的会话不进入普通列表、搜索和冷接管。所属插件可以为运行中的 Agent 开放原生 Session 控件，客户端通过显式地址保留引用，无需目录项。这修正了此前两种状态的可见性差异，无需增加产品会话格式，也不把练习伪装为子 Agent。

平台增加带实际挂载确认的设置导航、随调用方生命周期释放的新建会话拦截器、按会话约束的原生页面、视图实际显示观察和稳定标签定位接口。上游只能通过全局开发者设置开放轨迹，也无法让所属插件约束单个原生页面。临时约束填补示例与练习会话的需求，不修改全局偏好。顶栏与正文读取同一份会话视图列表和原生选择状态。现有插槽优先级支持替换侧栏，无需补丁。可复用定位浮层属于 UI 引导扩展，故事模式只负责目标、文案及推进条件。

启动器在独立的 PaperMoon profile 中使用原生 DSH 组合包。扩展组合包独立于可开关的故事模式组合包；关闭故事模式后仍可找到已安装的卡片，所属练习 Agent 停止并退出，进度保留。启动和热重载保留用户选择。原 Web profile 留给原版 Web 命令，不自动复制配置或数据。

本实现落实了 [Playbook 与故事模式决策](2026-09-24-playbook-and-story-mode.zh.md)确立的边界。[Effort 提示决策](../simplification/2026-09-25-story-mode-effort-guidance.zh.md)继续生效：提示观察模型能力与用户选择，不锁定或覆盖请求。[章节文档](../../../../docs/story-mode/README.zh.md)维护交互需求，不记录交付状态。

示例与练习 Session 通过 `uiWorkspace.openSession` 进入默认页面。故事模式不另设 SessionProvider、不计算页面阶段，也不强制选择视图。打开设置或切换视图时保留章节状态，只有进入章节、更换目标会话或明确点击新建会话才发起导航。章节列表和主体介绍仍由章节提供，操作引导、配置反馈和“继续”都放在侧栏当前小节。

上游主页面通过会话引用信息发现当前会话。因此，显式私有地址在客户端 `byId` 中提供引用信息，同时不进入普通 `ids`、Host 列表、搜索或冷接管。这保留了默认挂载与浏览器标题行为，无需将练习伪装为子 Agent。原生顶栏也读取会话自己的标题投影。控制器强制示例只读，由消费者校验输入；私有模型选择不改变默认值。页面约束隐藏工具及文件接收，斜杠和引用输入按普通文本处理。释放一份约束不会清除其他所属插件的限制。

固定示例使用独立、合法、只读的 DSH Session 种子，时间戳为零，不含用量，创建与恢复均不执行推理。对话与轨迹读取同一提示词及消息，绝不进入练习 Session。此前的文本对话页面和独立只读轨迹工厂已删除。世界线检查仍使用通用显式检查投影，因此保留该机制。

两个轨迹步骤保留当前对话。可复用浮层突出原生标签，等待目标可见并跟随布局变化，不点击或移动焦点。Escape 收起提示，侧栏可重新显示。只有原生视图准备就绪，且目标回复对应的记录行实际可见，才确认查看；后台投影、进入步骤、显示或收起提示都不满足条件。原生视图选择在刷新后保留。离开章节或卸载插件时释放提示、约束及已选中的私有页面。

介绍步骤改为读取当前配置，不再在章节进度中保存设置页查看标记或所选模型路由。任意模型配置齐备后即可手动推进。配置读取失败可重试，介绍不发送推理请求。新练习只固定有效的已有选择，否则由用户通过原生选择器选择。这避免了默认模型缺失或无效时静默替用户选择其他模型。

首次完成的练习回合固定查看目标，不随 Agent 最近一次请求变化。查看轨迹期间及完成本章后，页面约束都允许继续对话，发送和停止由原生执行状态控制。后续失败不撤销已完成进度。进度保存首次成功回合及查看确认，模型选择和会话历史由 DSH 保存。移除无用的进度字段，不迁移或改写已有练习存档。

允许继续对话后，仅观察视图就绪无法识别用户看到的是哪一次交流。因此，轨迹补丁为原生单条记录行添加来源事件序号属性，聚合摘要行不提供该属性。引导扩展观察 DOM 实际可见性，包括裁剪与遮挡；故事模式提供目标会话和首次回复序号。两个轨迹小节均使用该定位属性。这项小范围平台扩展避免另写轨迹渲染器或在客户端重建历史。浏览器回归覆盖原生列表尾部仅显示后续回复，直到滚动到首次回复才确认查看的场景。

Host 与 Client 共用需求维护的原文。故事模式 RPC 错误以键标识本地化消息，其他失败保留底层文本。单元检查逐项核对故事模式文本、固定示例与双语需求。为章节约束新增的原生输入框占位文字也须在需求中给出原文。这落实了已有文本依据决策，不将需求编写移入实现过程。

## 考虑过的替代方案

保留启动器产品叠加配置，会使它高于用户的插件选择。原生组合包让 DSH 负责开关和重载。把对话逻辑都放进故事模式，会让可复用机制依赖章节规则。另写对话或轨迹界面会逐渐偏离 DSH。仅嵌入 `conversation.content`，或在章节页面中再包裹完整页面，同样绕过正常导航及共享顶栏状态。原生导航配合局部约束，才能保留用户正在学习的真实体验。伪造客户端 Session 绑定会绕过生命周期和历史校验；合法的预置 Session 配合明确的只读所有权保留这些保证，侧栏引导则区分示例记录与真实执行。

独立的提示决策已否决锁定 effort。示例保持硬编码，只有真实练习使用模型。复用 DSH 持久化和请求边界记录，无需另建产品对话格式及迁移机制。

## 影响

可以移除故事模式而保留文本对话扩展。保存的尝试将进度绑定到一个练习会话，重新开始后拒绝旧操作。重新开始分配全新练习，保留以前的会话文件。平台不感知章节名称和内容；后续改动仍须保证已实现章节可以从头完成。

验证使用主库单元测试、实际托管的 DSH 构建，以及确定性的集成和浏览器测试，不用复制源码树或付费模型调用代替应用验证。原 Web profile 的设置不会静默导入 PaperMoon profile，用户通过正常设置界面配置。
