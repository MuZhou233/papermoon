# Agent Note: 故事模式分层

Status: implemented

[English](2026-09-25-story-mode-layers.md) | 中文

## 问题

章节驱动开发需要职责明确的共用运行机制。引导、原生对话和轨迹检查须在各产品功能间保持一致，每章则负责自己的教学与推进。

## 决定

PaperMoon 分为平台、扩展和故事模式三层。DSH 补丁属于平台，扩展负责可复用插件，故事模式负责章节内容与专属推进策略。依赖向下并保留目录归属。[架构](../../../../docs/architecture.zh.md)维护职责图，[命名决策](2026-09-24-playbook-and-story-mode.zh.md)维护产品术语。

原生 PaperMoon 配置独立组合扩展与可开关的故事模式包。DSH 负责安装、启用、重载和持久用户选择，原版 Web 配置继续维护自身设置。设置与运行数据保存在托管源码之外，由所属方明确配置。

原生 Session 导航负责标题、视图、输入与请求历史。通用设置导航、新会话拦截、逐 Session 页面租约、稳定视图锚点及展示观察属于可复用平台接口。租约组合多个所有者的限制，并只释放自身约束。明确的私有会话引用可开放原生页面，同时保持在工作区列表、搜索和冷接管之外。控制器按所属方规则接纳输入与模型选择，只读开放保护预置记录。共用检查投影继续服务于世界线检查。

文本对话扩展继续提供原文提示词、无工具 Agent、模型元数据和持久请求检查，由产品层决定使用时机。当前第一章按[存档决策](2026-09-28-storyline-playbook-saves.zh.md)使用普通 Playbook 演绎，旧章专用示例、尝试文件和重启代码已移除。

定位浮层属于引导扩展，跟随真实 DOM 可见性、几何、裁剪及遮挡，并提供键盘关闭。稳定的原生账本来源事件锚点允许所属方定位某条回复，聚合行保留聚合身份。原生视图选择和通用请求检查继续使用平台自身记录。

[上下文引导](2026-09-29-story-mode-contextual-guidance.zh.md)现在在右侧跟随 Playbook，保留左侧导航。[创作策略](2026-09-29-plaintext-playbook-authoring.zh.md)提供能力检查，[思考强度决策](../simplification/2026-09-25-story-mode-effort-guidance.zh.md)保留用户选择。完整双语文案由需求独立维护。

## 考虑过的替代方案

启动器叠加配置会覆盖插件选择，原生组合包让 DSH 负责开关和重载。将通用对话机制放入故事模式会反转依赖，平行对话或轨迹渲染又会偏离原生行为。仅嵌入对话正文或包裹完整页面会绕过普通导航和标题状态。

伪造客户端 Session 绑定会绕过生命周期与历史校验。需要通用预置只读记录时，仍应使用有效 Session 与明确所有权。真实模块记录保留请求边界，避免平行会话格式。原生行锚点可精确观察可见性，客户端继续消费既有历史。

思考强度锁定由所属决策否决。以访问设置作为准备条件，会要求已有有效模型的用户重复操作；当前可用性和明确选择提供有意义的条件。进度依赖最新回复会让继续对话改变学习目标，持久的首个合格回复可在后续失败后保留进度。

## 影响

共用平台与扩展能力独立于章节删除。故事策略可卸载并保留内容和会话，受保护操作等待提供方恢复。主仓库 Notes 负责补丁理由，直接契约与测试随登记的 DSH 补丁维护。

验证使用主库测试、托管 DSH 源码检查及确定性真实应用集成／浏览器测试，临时数据验证实际请求与原生页面。当前格式政策保留现有运行文件，历史教程行为由 Git 保存。
