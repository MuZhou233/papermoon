# Agent Note: 只维护当前产品格式

Status: implemented

[English](2026-09-25-current-format-only.md) | 中文

## 问题

PaperMoon 不承诺产品迭代之间的数据兼容，但格式计数器、历史格式拒绝测试和旧演绎的只读路径，仍要求维护一套产品不支持的数据结构历史。

## 决定

产品数据库、Playbook 内容、编译产物、编辑器备份、编剧配置与演绎元数据直接使用当前结构，不另设格式版本号。读取器保留应用身份、结构校验和完整性检查。历史读取器、迁移、兼容分支和历史格式测试不属于当前产品范围。[开发指南](../../../../docs/development.zh.md#冻结修订数据)维护操作说明。

本决定替代[Playbook 命名决定](../architecture/2026-09-24-playbook-and-story-mode.zh.md)中的格式版本处理，以及[世界线决定](../architecture/2026-09-16-worldlines.zh.md)中的只读回退路径。已初始化的演绎必须有世界线根节点和选中路径，不为缺少这些记录的会话提供另一套读取方式。

草稿序号、编剧编辑序号、历史选择计数器和不可变内容修订版本仍属于正常产品行为。它们用于检测并发变更或表示用户作品，不是文件格式版本。DSH 协议字段、依赖版本和仓库维护格式仍遵循各自约定。测试继续覆盖当前格式的持久化、刷新、中断恢复和 Fork。

## 考虑过的替代方案

只为拒绝已知历史值而保留版本计数器，会继续维护兼容性矩阵，却不提供受支持的升级路径。将计数器全部重置为一，也会保留同一套机制。随计数器一起移除结构校验，则会丢失当前运行仍需要的无效输入与数据损坏检查。

## 影响

产品数据结构改变后，开发使用新建数据。已有运行文件不会被自动迁移或清理。跨迭代读取不属于交付要求，当前行为和数据完整性测试仍须通过。章节需求继续要求每个已实现章节都能在当前产品中从头完成。
