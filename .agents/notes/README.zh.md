# Agent Notes

[English](README.md) | 中文

## 用途与归属

Note 保存主库决定、动机、真实替代方案和影响。非平凡主库变更新增或更新所属 Note，机械性局部修改可以豁免。新增前搜索已有 Note。仅属于 DSH 补丁的决定遵循子模块 Note 规则并保留在补丁中。

按状态和分类目录查找 Note，不另设中央索引。文件名使用 `YYYY-MM-DD-topic.md`，日期表示首次提出该主题的时间。分类为 `feature`、`bug-fix`、`simplification`、`architecture`、`process` 和 `testing`。空分类无需占位记录。

## 活跃状态

每篇 Note 以 Agent Note 标题、空行和 `Status:` 行开头，状态后放置语言切换链接。两种语言保留机器可读的头部标记及相同状态，包括拒绝原因。正文标题翻译为对应语言。

| 目录 | 必需的中文章节 |
|---|---|
| `proposed` | 问题、方案、考虑过的替代方案、验收条件、风险 |
| `implemented` | 问题、决定、考虑过的替代方案、影响 |
| `rejected` | 问题、方案、考虑过的替代方案；状态中包含拒绝原因 |

首节是问题。已实施 Note 描述已交付事实，不保留提案或验收计划章节。路径、名称和职责变化时更新事实。不同的决定需要新的 Note，不能把旧结论改写为其反面。替代方案必须真实存在，不为满足模板而编造。

## 创建与转换

```sh
pnpm note new --class process --slug topic --title "Topic" --title-zh "主题"
pnpm note transition .agents/notes/proposed/process/2026-09-11-topic.md --to implemented --english prepared.md --chinese prepared.zh.md
pnpm docs:record .agents/notes/implemented/process/2026-09-11-topic.md
pnpm check:notes
```

创建命令接受 `--status`、`--date` 和拒绝原因 `--reason`。模板含未完成标记，替换后才能通过检查。创建 Note 不代表决定已经实施。

转换状态前，准备好包含目标状态和所需章节的英中文本，相对链接仍按 Note 原位置编写。工具校验后一起移动英文、中文和一致性文件，调整相对链接，并更新活跃文档中指向它们的引用。只有提案能转为已实施或已拒绝。作者需审阅准备好的文本。

## 替代与整合

新决定只替代旧决定的一部分时，保留两篇 Note，更新仍适用的事实，并互相链接。整合后的 Note 保留全部独有理由、替代方案、影响、验证要求和已知缺口后，才能删除旧记录的三份文件。同步更新所有指向旧文件的引用，让读者无需翻查 Git 历史也能找到解释。

已拒绝提案中的理由能帮助后来者避免重犯错误时，保留该记录。失去这项用途后，经审查再删除三份文件并更新引用，不因记录年久就自动清理。链接检查能发现失效引用，不能判断论据是否保留完整。

## 归档与冻结

仅归档其理由不太可能继续指导工作的已实施决定。涉及职责归属、数据、安全或是否重新采用某种方案的理由，只要仍有参考价值，就保留为活跃记录。不要按年限、数量或字数上限归档。

```sh
pnpm note archive .agents/notes/implemented/process/2026-09-11-topic.md --date 2026-09-11
pnpm check:notes
```

命令将英文、中文及一致性文件一起移入归档分类目录，保留已实施状态，为英中两版加入相同的 `Archived:` 日期，再封存全部文件。归档时，正文只允许增加归档日期。归档内的链接保留原样，活跃文档中指向归档的引用会随之更新。

封存后不得编辑、翻译、重命名、移动或删除三件套。归档清单记录内容哈希，只能追加。检查同时比较文件、清单和已提交的历史，即使一并改写哈希，也不能修改已封存的内容。归档只供历史参考，不作为当前规范，也不随当前文风和链接规则更新。

设置 `PAPERMOON_ARCHIVE_BASE_REF` 可指定可信的 Git 比较基准。本地默认使用 HEAD；确认仓库尚无提交后，才使用空基准。明确指定的基准无法读取时会报错。CI 使用 PR 基准或推送前提交，因此修改清单不能改变比较基准。
