# Agent Notes

[English](README.md) | 中文

## 用途与归属

Note 保存主库决定、动机、真实替代方案和影响。非平凡主库变更新增或更新所属 Note，机械性局部修改可以豁免。新增前搜索已有 Note。仅属于 DSH 补丁的决定遵循子模块 Note 规则并保留在补丁中。

以生命周期和分类目录作为目录清单，文件名使用 `YYYY-MM-DD-topic.md`，日期是首次提出该主题的时间，不设置中央索引。分类为 `feature`、`bug-fix`、`simplification`、`architecture`、`process` 和 `testing`。空分类无需占位记录。

## 活跃状态

每篇 Note 以 Agent Note 标题、空行和 `Status:` 行开头，状态后放置语言切换链接。两种语言保留机器可读的头部标记及相同状态，包括拒绝原因。正文标题翻译为对应语言。

| 目录 | 必需的英文节名 |
|---|---|
| `proposed` | 问题、方案、考虑过的替代方案、验收条件、风险 |
| `implemented` | 问题、决定、考虑过的替代方案、影响 |
| `rejected` | 问题、方案、考虑过的替代方案；状态中包含拒绝原因 |

首节是问题。已实施 Note 描述已交付事实，不保留提案或验收计划章节。路径、名称和职责变化时更新事实。不同的决定需要新的 Note，不能把旧结论改写为其反面。替代方案必须真实存在，不为满足模板而编造。

## 创建与转换

```sh
pnpm note new --class process --slug topic --title "Topic" --title-zh "主题"
pnpm note transition .agents/notes/proposed/process/2026-09-11-topic.md --to implemented --english prepared.md --chinese prepared.zh.md
pnpm docs:record .agents/notes/implemented/process/2026-09-11-topic.md
pnpm check:notes
```

创建支持 `--status`、`--date` 和拒绝原因 `--reason`。模板含明确的未完成标记，替换前检查会拒绝。创建不代表决定已经完成。

转换接收含目标状态及章节的已准备双语内容，准备文件中的相对链接按照原 Note 位置解释。工具先校验，再移动完整三件套、调整相对链接并修复活跃文档中的入站引用。只有提案可以转换为实施或拒绝。作者仍需审查准备内容。

## 替代与整合

部分替代时保留双方 Note，更新仍有效的事实并交叉链接。完整整合只有在新归属记录保留全部独有理由、替代方案、影响、验证要求和已知缺口后，才可以删除旧三件套。修复全部入站引用，不把 Git 历史当作唯一剩余解释。

拒绝提案仅在能阻止合理且有意义的错误时保留，否则删除三件套并修复引用。这些操作需要编辑审查，不是按年龄自动清理。链接检查能发现悬空引用，不能证明全部论据都已保留。

## 归档与冻结

仅归档其理由不太可能继续指导工作的已实施决定。有价值的归属、数据、安全和重新引入理由保持活跃。不要按年龄、数量或字数预算归档。

```sh
pnpm note archive .agents/notes/implemented/process/2026-09-11-topic.md --date 2026-09-11
pnpm check:notes
```

命令将完整英文、中文及一致性三件套移动到归档分类目录，保留实施状态，插入相同的 `Archived:` 日期并封存每个文件。这是归档时唯一允许的正文变化。出站链接保留历史内容，活跃文档中的入站引用会被修复。

封存后不得编辑、翻译、重命名、移动或删除三件套。只允许追加的清单记录内容哈希。检查将文件和清单一起与已提交历史比较，改写哈希无法授权修改。归档不属于当前规范，不参与持续变化的文风和出站链接规则。

`PAPERMOON_ARCHIVE_BASE_REF` 指定显式可信 Git 基准。本地默认使用 HEAD，经验证的无首次提交仓库使用空基准。显式基准不存在时报错。CI 从 PR 基准或推送前提交获取基准，不从变更可控制的清单读取。
