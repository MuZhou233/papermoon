# 开发指南

[English](development.md) | 中文

## 初始化与命令

使用根目录声明的 Node 和 pnpm 版本。先安装主库依赖，再调用仓库工具。执行脚本时若依赖已过期会报错，不会自动安装。已记录的 Gitlink，包括有意暂存的更新，是唯一的 DSH 版本依据。

| 命令 | 效果 |
|---|---|
| `pnpm run setup` | 重置 DSH、应用已登记补丁、安装锁定的 DSH 依赖 |
| `pnpm build` | 清理 DSH 声明的构建产物并执行其官方构建 |
| `pnpm start -- --port 3081 --no-open` | 启动原版 Web；参数分别通过 argv 传递 |
| `pnpm check` | 主库类型、lint、测试、文档与 Note 检查 |
| `pnpm check:docs` | 主库文档与检查器来源检查 |
| `pnpm check:notes` | 活跃 Note 与不可变归档检查 |
| `pnpm check:patches` | 重建源码并执行登记的 DSH 交付检查 |
| `pnpm test:smoke` | 构建后使用临时真实 Web 进程验证，不调用模型 |

名为 setup 的包脚本必须通过 `pnpm run setup` 调用：`pnpm setup` 是 pnpm 的保留命令。自动化使用明确的脚本形式。

## 编辑与升级

自定义插件保留在主库，源码定制保存在[补丁](../patches/README.zh.md)中。初始化会移除 DSH 内未跟踪且未忽略的文件，不会清理已忽略的文件。重新初始化前导出需要保留的源码修改。用户数据放在受管 checkout 之外。

更新 DSH 时，选择官方提交，暂存新的 Gitlink，调整补丁及所需检查，然后执行初始化、构建、补丁检查和启动验证。主库检查器源码单独审查，不随 Gitlink 自动更新。两套依赖锁文件各自独立。

## 故障处理

缺少构建产物时会明确提示构建。已有产物通过显式构建命令刷新。补丁应用失败会恢复固定源码并停止；修复补丁后重新初始化。未知检查脚本、未登记文件和源码差异会使补丁验证失败。

初始化不会启动服务。Web 保持连接到终端，使用正常中断或终止信号停止。启动测试使用临时数据和随机回环端口，并等待进程退出。[测试规范](testing.zh.md)说明交付证据。
