# Playbook 创作设计

[English](playbook-authoring.md) | 中文

本文定义纯文本创作与按范围开放编剧工具的能力。[故事模式](story-mode/design.zh.md)决定故事线各阶段开放哪些能力，[第一章](story-mode/fogbound-earthshine/01/README.zh.md)用这些能力创作第一个角色。[架构决策](../.agents/notes/implemented/architecture/2026-09-29-plaintext-playbook-authoring.zh.md)维护理由，运行接口和存储字段由插件契约维护。

## 纯文本内容

系统提示词和开场消息分别支持纯文本模式，可以独立选择。它们属于 Playbook 创作内容，随草稿保存并冻结在版本中，不是脚本编辑的简易入口。现有脚本创作仍是独立能力，调用方无需同时开放全部模式。

系统提示词是一段原样文本。开场消息是有序列表，每条具有 user 或 assistant 角色及原样正文。保存、创建版本和初始化演绎时保留空白、换行、角色与顺序。纯文本值不执行脚本，也不展开模板。两个部分各自选中的模式决定其如何进入演绎上下文。

普通草稿允许未完成或为空的内容。故事线推进和演绎准备可以规定各自前置条件，这些条件不成为所有存储操作的通用限制。

## 手动编辑器

两个纯文本编辑器共用语法高亮、查找、撤销重做及可见的保存状态。提供手动选择的 Markdown 和 XML 高亮，默认 Markdown；自动识别为可选能力。高亮只是展示偏好，切换时不改写内容、不改变创作模式，也不清除待保存修改。Markdown 或 XML 语法不完整不阻止保存。

创作模式和语法高亮放在与编辑框相连的紧凑工具栏中。高亮控件显示明确标签、当前语言及展开图标；菜单标明当前选项，并支持键盘选择。采用 DSH 的主题颜色、控件尺寸和焦点状态。消息角色标签沿用轨迹表格的配色，user 使用蓝色，assistant 使用紫色。明暗主题的下拉菜单均使用不透明背景。每条开场消息使用独立卡片，顶部放置序号、角色控件及带有名称的排序／删除图标。窄屏下控件换行，编辑区域保持在框内。

开场消息支持新增、删除、编辑正文、在 user 和 assistant 之间修改角色，以及调整顺序。新增消息默认使用 assistant，用户可以更改。相邻消息可以使用相同角色，空列表有效。排序保留每条消息的正文和角色，除指针交互外，还须提供键盘可用的操作。

沿用现有草稿保存、未保存修改和冲突处理体验。编剧保存另一项修改时，不能静默丢弃本地内容。需要使用已保存内容的操作，须先处理待保存修改。高亮设置属于编辑器偏好，不是模型指令或故事线进度。

## 能力模块与编剧

工具按系统提示词、开场消息、程序、文案目录、历史和编译能力组织。系统提示词工具读取和修改对应内容；开场消息工具支持读取、新增、删除、正文修改、角色修改和排序。拆分其他模块时保留现有操作语义。

工具目录、参数范围、帮助与执行使用和手动编辑相同的能力集合。普通 Playbook 开放适用能力，故事存档再应用当前阶段限制。通用状态与帮助只展示允许访问的内容和操作，不能通过完整元数据结果或历史／差异结果泄露尚未开放的内容。

已有编剧会话随能力变化更新工具。恢复及 Fork 的会话重新获取当前权限，冻结的编剧提示词或此前注册的工具不冻结授权。每次执行重新校验允许的操作和内容范围，旧调用不能绕过限制。元数据编辑、历史恢复和模式切换须遵守与直接编辑相同的规则。

编剧不能编辑故事线绑定或进度，也不能伪造章节 tag，这些记录由故事模式编排负责。编剧保存的内容可以满足章节的内容条件，但人工继续仍由用户操作。仅开放工具不会推进步骤。

人工与编剧编辑同一内容时，保留对象读取保护、冲突检测及原子保存。操作被拒绝或发生冲突时，不保存部分修改。读取记录不授予能力权限，能力权限也不替代必要的读取记录。工具模块属于可复用扩展层，通过共用能力接口接收策略，不导入故事线内容。

## 演绎与章节边界

演绎初始化读取两个部分当前模式选定的已保存内容，冻结一致的上下文。启动演绎本身不代表章节完成。以执行成功为通过条件时，章节提交须对应该次演绎使用的内容和合格记录，不能混入之后的草稿修改，也不能覆盖这些修改。故事进度可以推进，当前草稿仍保留后续创作。

[存档设计](story-mode/design.zh.md#章节提交与回顾)维护完成状态、tag、重试与只读回顾的持久性规则，章节需求决定哪次操作满足条件。本文不规定工具名称、参数 schema、数据库字段或纯文本与脚本内容的组合实现。

## 验收场景

- 分别保存并重新加载两个部分的纯文本内容，版本和实际演绎上下文保留正文、角色与顺序。
- 切换 Markdown／XML 高亮时不改变文本或丢失未保存内容，语法不完整也能保存并按原文使用。
- 新增、删除、编辑开场消息，修改角色和排序，覆盖空列表与相邻消息同角色的情况。
- 手动控件、已注册编剧工具、帮助、状态及执行使用相同范围，直接和间接的越权读写均被拒绝。
- 阶段变化后更新已有编剧会话，在恢复、Fork 和旧工具调用执行时重新校验权限。
- 验证人工与编剧并发修改、必要读取记录及拒绝批次，不静默覆盖内容，也不保存部分修改。
- 演绎启动后继续修改草稿，再完成章节；提交保留演绎使用的内容与合格记录，后续草稿修改保持完整。
