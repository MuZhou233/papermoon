# 故事模式需求

[English](README.md) | 中文

故事模式（Story Mode）按章节组织体验。这些文档定义预期体验及其约束。开发与交付继续沿用现有流程。

## 文档组织

每章使用带编号的目录，以 README 说明目标和步骤顺序，每小节使用带编号的独立 Markdown 文件。按[文档规则](../AGENTS.md)维护英文、中文和配对文件。

每个小节记录用户操作、可观察结果、所需的 UI 和引导、推进条件及验收场景。本入口文档维护共用交互要求，各章引用，不重复定义。需求文档不记录实现或交付状态。架构、API 和实现决策由工程文档及 Agent Notes 维护。

## 共用交互

### 入口与章节导航

左侧栏增加“故事模式”入口。页面显示章节列表、各章完成状态和进入按钮。进入章节后，将侧栏原工作区列表区域替换为章节进度，区分已完成、当前和未开始的步骤。点击进度列表不能跳过未完成的步骤。

提供返回章节列表的入口，离开章节时恢复普通工作区列表。章节激活期间，新建会话入口不能绕过当前步骤或创建普通会话。

沿用 DSH 的主题、排版、控件和响应式习惯。配置页可以从章节中打开，关闭后回到原步骤，并保留进度。

### 推进方式

支持两类推进条件：用户操作产生的可验证结果，以及用户明确点击继续。每个小节规定自己的条件。人工推进的步骤如有前置条件，满足后只解锁“继续”，不自动前进。

### 保存进度与重新开始

同一安装配置下保存章节进度和练习会话，刷新、退出及再次进入时继续本次练习。“重新开始”重置本次进度，真实对话练习使用没有既有对话历史的新会话。练习会话仅通过故事模式恢复，不出现在普通会话列表中。

恢复页面不自动重发模型请求。请求失败、取消或中断时保留练习，允许用户重试。章节完成后明确显示完成状态，提供返回章节列表和重新开始的操作。

## 实现约束

遵循[架构职责](../architecture.zh.md#职责)：故事模式插件负责章节定义、进度编排、专用 UI、引导和预置内容；模型配置、请求执行、会话持久化等通用机制由其他包提供。优先通过这些机制的公开扩展点接入。必要的 DSH 补丁遵循[补丁范围规则](../../patches/README.zh.md)，尽量缩小范围，确需扩大时说明理由。

后续章节需要调整架构时，所有已实现章节仍须能在当前版本从头完成。操作说明和预置内容可以更新，同时保留教学目标与预期结果。保存进度不意味着支持旧进度或旧会话格式的迁移。

## 共用验收场景

- 侧栏入口打开章节列表，显示完成状态及进入按钮；进入和离开章节时，工作区列表区域正确替换与恢复。
- 进度区分已完成、当前和未开始步骤；进度列表和新建会话入口均不能绕过规定顺序。
- 打开、关闭配置页后仍停留在原步骤；宽屏和窄屏界面均沿用 DSH 风格。
- 刷新或再次进入恢复本次进度和练习会话；重新开始重置进度，并为真实练习使用全新对话。
- 练习会话不出现在普通列表，恢复页面不重发请求。
