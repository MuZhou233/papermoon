# 故事模式需求

[English](README.md) | 中文

故事模式（Story Mode）按故事线、章、节和步骤组织体验。[存档设计](design.zh.md)维护 Playbook 存档、导航、章节提交和回顾规则，[雾锁地照](fogbound-earthshine/README.zh.md)是首条故事线。这些需求沿用现有开发与交付流程。

## 文档组织

每条故事线使用独立目录，每章使用带编号的目录。故事线 README 维护名称、简介和章目录，章节 README 维护主题与节顺序。每份带编号的节文档记录步骤、用户操作、可观察结果、引导、推进条件和验收场景。按[文档规则](../AGENTS.md)维护英文、中文和配对文件。

本文维护共用展示和文本规则。存档设计维护共用生命周期，[创作设计](../playbook-authoring.zh.md)维护可复用的编辑及编剧能力。章节引用这些维护文档，不重复定义。需求不记录实现或交付状态；架构、API 和决策由工程文档及 Agent Notes 维护。

## 文本依据

故事模式提供或改写的所有文本，都须在需求文档中给出明确原文，包括名称、介绍、引导、控件、状态、异常提示、示例和预置提示词。共用文本只有一个维护位置，章节文本由概述或所属节维护。中英文界面分别使用确认的措辞，声明为固定原文的文本不随界面语言改变。

讲解、示例、控件和状态文案在需求中确定，不将措辞留到实现阶段。这些段落就是界面须使用的正文。新增内容缺少文本时，先在需求中确定，再实现对应内容。已有代码不代表文本已经确认。禁止在实现过程中自行增补、润色、缩写或替换确认原文。Playbook 尚未提交的创作内容仍称为“草稿”，这一术语不表示讲解文案的状态。

教学正文采用论文式论述，先定义概念、解释机制及适用条件，再提出实践建议。概念依照前置关系在各节逐步展开，正文独立完成论述，示例及分析随后承接讲解。实践部分使用建议语气，操作引导单独维护并采用明确动作表述。每节按概念与机制、实践建议、示例及分析、操作引导的顺序组织；正文中的“示例”可以指一种提示词内容，具体教学示例的引用与分析由后续示例部分维护。

中文教学正文中的核心术语首次出现时采用“中文（英文）”，后文使用中文；PaperMoon、Playbook、Markdown、XML 等专有名称保留原文。英文正文采用自然英文。消息角色的技术值保持原样，中文说明使用系统（system）、用户（user）、助手（assistant）等对应写法。

动态文本须给出完整模板及变量来源。原样复用的控件注明来源，不重复抄录上游措辞。模型名称和可用思考强度来自模型元数据，真实回复来自演绎，底层错误来自所属服务。围绕这些数据新增的文本仍须给出明确模板。

## 共用交互

### 展示与导航

沿用 DSH 的主题、排版、控件和响应式习惯。左侧栏保留普通工作区、存档和会话导航，不再被章节进度替换。中央用于编辑、编剧对话和演绎，右侧“故事引导”面板承载当前存档的教学内容。

引导跟随 Playbook，在其编辑页、所属编剧会话和演绎之间保持连续，没有会话的编辑页也能展示。切换存档时切换引导上下文，进入无关页面或普通会话时隐藏，返回后恢复位置。打开配置不改变章节进度。隐藏或关闭引导不解除存档的能力限制，新建会话等通用入口仍须遵守这些限制。进入、切换和恢复存档遵循存档设计。

引导使用紧凑的顶部区域显示存档、章、节和步骤位置；独立滚动的正文按讲解、示例、分析、操作引导的顺序完整展示内容；底部保留前置条件反馈及继续控件。本章进度可展开为小节标题与状态列表。存档入口与引导统一采用 DSH 的主题颜色、排版、间距、边框和控件尺寸。用户可以边阅读边操作中央界面，通过创作操作将内容写入 Playbook。

示例采用轨迹视图的有序条目、角色标签、选中行强调及原文详情。指针或键盘选中条目后，详情展示完整正文并保留原有换行。窄面板按上下结构排列列表与详情。显示标签跟随教学术语：第一节使用输入与回应，后续小节引入消息角色。示例选择仅改变当前展示的详情。

新开放的功能在中央控件旁显示“新解锁”标签及功能名称，对应编辑器标签和区域同时高亮。开场白编辑、系统提示词编辑、模型选择、思考强度与演绎分别在所属小节开放时获得提示。对应内容保存、有效模型选定或演绎启动后，提示结束；刷新后依照当前存档状态恢复。功能范围由现有进度与授权决定，提示仅影响展示。

对话与轨迹使用真实的 DSH 页面，保留原生顶栏、标签、消息、输入框及响应式布局。创作使用通用编辑页面，并应用当前能力范围。原生模型配置、模型和思考强度选择器、输入框及发送／停止控件沿用现有标签和无障碍文本。章节需求补充自行编写的引导或控件。引导只作用于所属存档，不改变普通会话或全局默认值。

### 展开与更新提醒

新建存档后进入编辑器，右侧栏保持收起。浮层锚定原生展开按钮，说明如何打开故事引导。用户可以展开侧栏，也可以通过关闭控件或 Escape 关闭浮层。引导展示后清除首次提示；浮层显示期间由它承担首次提醒。主动继续已有存档时展开引导。后续交互尊重用户收起面板、切换右侧工具和调整宽度的选择。进度更新不自动展开面板、不切换标签，也不抢焦点。所属页面顶栏保留“故事引导”入口，供用户返回。

右侧栏收起时，在展开按钮左侧显示未查看的进度更新提醒。右栏已展开但显示其他工具时，在“故事引导”标签显示未读标记。点击提醒打开当前引导，成功展示最新状态后才清除；多次未查看更新合并为一个提醒。可见引导中已经展示的更新不需要未读标记。提醒跟随所属存档，不能显示在另一份存档名下。

与其他工具共用右侧承载区域，保留它们的标签和状态。不为引导增加另一列，也不清除其他工具。面板开合、阅读位置和提醒属于展示状态，不成为另一份故事进度。

### 定位浮层与窄屏

完整讲解与示例保留在引导面板。操作涉及左侧栏或中央区域时，提供锚定真实控件的简短提示，文本采用所属节的操作引导。用户可以关闭并重新显示浮层；保留键盘与指针操作，不模拟点击，也不遮挡目标。目标缺失、隐藏或被遮挡时，等待其可见，不指向其他控件。

窄屏使用全屏引导面板。定位面板之外的控件前，先收起全屏引导，保留阅读位置和返回入口，目标可见后再展示浮层。改变窗口宽度或关闭提示都不完成步骤、不丢弃编辑，也不改变存档能力。

### 推进方式

支持用户操作产生的可验证结果，以及明确点击继续两类推进方式。每步声明自己的条件。人工步骤满足前置条件后只解锁继续，不自动推进。不以阅读时长、滚动到底或答题作为推进条件，也不生成虚构的完成事件。

## 实现约束

遵循[架构职责](../architecture.zh.md#职责)：故事模式负责故事线内容、进度编排和阶段规则。可复用的创作、工具、配置、请求与持久化由扩展层或平台层维护，通过公开扩展点接入。必要的 DSH 补丁遵循[补丁维护范围](../../patches/README.zh.md)。

右侧承载层支持 Playbook 页面上下文与真实会话。[引导决策](../../.agents/notes/implemented/architecture/2026-09-29-story-mode-contextual-guidance.zh.md)记录职责与上下文隔离，[插件契约](../../plugins/story-mode/README.zh.md)说明接入。需求继续独立维护产品行为，参数协议由实现契约负责。

后续改动须保留仍采用的章节的学习目标与完成路径。明确废弃的章节设计从需求集合中移除，不增加兼容样本或历史格式测试。沿用[当前格式规则](../development.zh.md#冻结修订数据)，不增加旧存档迁移支持。

## 共用验收场景

- 新建存档后核对右栏收起及展开按钮上的浮层。通过控件或 Escape 关闭，再手动打开引导；引导展示后清除浮层，主动继续已有存档时展开引导。
- 使用指针和键盘查看轨迹示例，覆盖多行内容与窄屏布局，保留教学标签、消息顺序、原文及空白创作状态。
- 各项能力开放时显示标签及编辑器强调；保存对应结果或启动演绎后清除提示，刷新和切换存档后保持正确范围。
- 导航标明当前存档、章、节和步骤，进度导航及其他入口均不能绕过条件或能力范围。
- 在没有会话的编辑页打开引导，再切换所属编辑器、编剧对话和演绎，保留上下文及阅读位置；访问配置保留进度，无关页面隐藏引导。
- 切换存档后，内容与提醒分别隔离，左侧导航和其他右侧工具标签保持完整。
- 收起引导或切换其他工具后推进进度，在规定位置显示提醒，不自动展开或抢焦点；合并更新，仅在展示最新状态后清除提醒。
- 定位左侧和中央的真实控件，关闭并重新显示浮层，验证键盘与指针操作；目标缺失或被遮挡时不显示错位提示。
- 窄屏打开全屏引导，定位外部控件后返回同一阅读位置，不丢失编辑。
- 人工条件只解锁继续，不自动推进；自动条件使用实际完成的操作。
- 显示、隐藏或离开引导均不改变完成条件，也不绕过授权；离开时释放所属提示，不改变全局偏好。
- 每条新增界面文本均对应需求原文、明确模板或记录的原生控件／数据来源。讲解与示例是完整需求正文，阅读不调用模型，也不填入创作内容。
