## 体验与界面

主体展示下方三段介绍，并始终保留“打开模型配置”按钮。简短操作引导、配置状态及“继续”放在侧栏聚焦的小节中。允许使用任意提供方。关闭模型配置后回到本步骤，不丢失进度。

通过已有机制读取模型及必要凭据是否齐备，不另建 API Key 表单或模型选择器，也不发送验证请求。检查是否存在至少一个配置齐备的模型，不要求已选默认模型或当前选择有效。凭据要求遵循各提供方的实际配置，不假定所有提供方都需要 API Key。配置齐备不代表真实请求必然成功，第四节会让用户实际体验模型回复。

本次检查不替用户选择或切换全局及练习模型。真实练习初始沿用有效的当前选择；没有有效选择时，由用户通过原生选择器选择配置齐备的模型后发送。

>
> 在第零章 hello world 中，你将先查看一段对话示例，再亲自与模型对话，并通过轨迹了解模型收到的请求和返回的回复。

| 配置状态 | 原文 |

控件使用[共用文本](../README.zh.md#共用文本)。模型配置页复用 DSH 原生模型页面及其文案。

## 推进条件

当前存在至少一个配置齐备的模型时，解锁“继续”。此时查看配置页为可选操作，“本次已查看配置页”不作为独立前置条件。没有有效模型时，要求先通过提供的入口完成配置再继续。正在检查或无法读取配置时，“继续”保持不可用，侧栏显示对应状态。

配置变化、刷新、再次进入和重新开始后，重新检查当前配置。补齐配置后只解锁“继续”，不自动推进。用户点击“继续”才完成本步骤并进入[对话示例](02-conversation-example.zh.md)。重新开始时已有配置齐备的模型，也不必再次查看配置页。

## 验收场景

- 主体显示确认的介绍原文和配置按钮，操作引导、配置状态及“继续”位于侧栏聚焦的小节中。
- 任意模型配置齐备即可继续，不强制查看配置页；未选默认模型或默认选择无效时同样适用，检查不替用户选择或切换模型。
- 没有有效配置时不能继续，并引导用户打开配置页；只查看页面不满足条件，至少一个模型配置齐备后才解锁“继续”。
- 检查中或无法读取配置时不能推进。重试、刷新、再次进入和重新开始均依据当前配置，不依据已保存的查看标记。
- DeepSeek 之外的提供方也能满足要求，遵循其凭据要求，不要求重新填写已有凭据。
- 本小节不发送模型请求，配置齐备后仍须明确点击“继续”才推进。
