# 测试与交付

[English](testing.md) | 中文

## 主仓库

开发过程中运行相关行为测试，提交前执行受影响的检查命令。CI 运行完整主库检查。测试覆盖解析失败、生命周期转换、Git 基准、进程取消和真实补丁重建。主库检查不构建或检查 DSH 源码，不设置逐文件覆盖率指标。

文档检查只读。即使实际仓库没有图表、类型摘录或归档，夹具仍验证合法与非法示例。机器检查验证结构、内容身份及可执行结果，无法判断翻译质量、替代方案是否充分，或整合是否保留全部重要论据。

主库流程区分工程就绪和产品体验反馈。主库变更不强制提供真实模型轨迹或 GIF。

## DSH 补丁

作用于子模块的变更遵循所检出版本的交付要求。在补丁清单中登记选定的包脚本和参数数组。成功运行只能证明这些检查通过，审查者确认所选检查满足 DSH 要求。DSH 所需的测试、文档和 Note 保留在补丁中。

源码比较与交付检查相互独立。补丁可应用不代表产品测试通过，预期补丁产生的修改也不会让 checkout 无效。[补丁维护](../patches/README.zh.md)定义检查命令配置。

## 隔离与 CI

测试分配临时 Git 仓库、文件和回环端口，在失败与成功时都释放资源。进程测试等待可观察的就绪状态，不假定固定启动时间。测试独立验证文件和进程结果，不依赖命令自述。

主库 CI 不获取子模块。集成工作流在 Gitlink、补丁、启动器、构建及相关依赖变化时运行，完成子模块初始化、构建、补丁检查及临时 Web 验证。仅修改文档不会触发 DSH 构建。

CI 中归档检查使用可信的 PR 基准或推送前提交。本地默认对照 HEAD，并为首个提交提供经验证的无历史仓库处理。显式提供但不存在的基准会失败。测试夹具建立自身 Git 历史，无法改写仓库的归档基准。
