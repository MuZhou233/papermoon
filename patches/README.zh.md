# DSH 补丁

[English](README.md) | 中文

## 源码归属

主仓库的 Gitlink 指定 DSH 官方基线。`series.json` 按应用顺序列出补丁文件，并登记交付所需的 DSH 包脚本。补丁和检查列表都为空时，表示 DSH 未作修改。有补丁就必须登记检查，审查者按子模块规则确认检查是否覆盖变更。

需要保留的定制修改必须写入补丁文件。在执行 `pnpm run setup` 前导出需要保留的修改；初始化重置 DSH 已跟踪变更并移除未忽略的未跟踪文件，不清理已忽略的凭据、依赖或主仓库运行数据。不要在这个会被重置的子模块目录中存放独立工作。

## 清单格式

```json
{
  "version": 1,
  "patches": ["0001-extension.patch"],
  "checks": [{ "script": "test", "args": ["-t", "extension"] }]
}
```

示例展示文件格式，检查命令需要按实际补丁选择。脚本名必须存在于补丁应用后的 DSH 包清单中。参数数组不经 shell 拼接。不要将修改预期输出的命令登记为验证。DSH 所需测试、文档和 Note 保留在补丁中；只有主仓库另有独立决定时，才在主仓库编写 Note。

按需生成包含二进制数据的 Git 补丁。补丁只能修改 DSH 内的文件。DSH 必须是主仓库的子模块，不能用符号链接或外部 worktree 代替。补丁文件及其上级目录也不能是符号链接。补丁的空白上下文行必须保留一个空格标记，主仓库 Git 空白检查因此仅对补丁文件放行行尾空白。重建时，`git apply --whitespace=error` 仍检查实际新增源码。应用补丁时使用 Git 暂存区，不作三方合并。遇到错误就停止，恢复上游基线，不再安装依赖。

## 已登记能力

补丁分别维护资源工作区、持久消息接纳与预置上下文、客户端选择与消息扩展，以及初始化会话展示。这些补丁只包含通用 DSH 行为；剧本规则和编剧快照由 PaperMoon 插件维护。登记的检查覆盖受影响的宿主和客户端测试、两端类型、lint、文档与无需密钥的会话回放。CI 还在子模块中运行 Python SDK 客户端测试。

## 验证与更新

`pnpm check:patches` 在临时检出目录中重建应用补丁后的源码，与实际子模块比较，并拒绝未登记文件。随后在 DSH 中执行已登记的检查，再比较一次源码。补丁产生的修改符合预期，不要求工作区没有改动。Git 已忽略的构建产物和运行文件不参与源码比较。

依据固定版本的 DSH 规则选择测试，命令执行器不推断这些义务。[开发指南](../docs/development.zh.md)说明完整升级步骤。交付时报告实际执行的检查及结果，引用 DSH 规则，不另存一份副本。

登记的 DSH 检查与 setup 使用相同的 CI 包管理器环境，依赖布局校验不会尝试再次安装依赖或配置本地 Git hook。

包含式联合补丁为工具 Schema 校验及两种语言的类型渲染器增加 anyOf。已保存结果恢复补丁允许依据更早的持久记录更正失败回执，保留消息与调用身份。两者均使用既有注册与 Session 机制，不包含产品专用规则。

字典类型补丁支持以 Schema 指定 additionalProperties，校验字典值并生成类型。回复显示补丁提供按 effect 管理的客户端登记，让指定预设保留中间 Assistant 正文。PaperMoon 登记主持人预设，DSH 默认行为保持不变。

工具参数诊断补丁在普通工具错误回执中保留 JSON 解析失败及其可提供的位置。格式错误的参数不会执行工具，合法 JSON 继续接受参数校验。

执行历史补丁增加区间选择、请求重建、接纳去重及客户端选择与操作扩展。PaperMoon 维护世界线树，从选中路径恢复剧本状态。补丁同步验证两种 SDK，并保留冻结的 Session 格式代际。

请求拼装补丁独立记录每次请求的消息引用和自定义正文，不改变对话历史选择。Loop、重建和不变量检查共用同一解析器。剧本拼装及检查页面由 PaperMoon 维护。

轨迹检查补丁增加会话内的只读数据源、有序上下文记录和导航插槽。PaperMoon 提供节点选择与双模式数据，共用的 DSH 轨迹保留搜索、详情、工具关联和请求检查。补丁不改变 Session 格式。

执行历史补丁让重 roll 和编辑重发共用用户输入接纳流程。对话操作插槽保持通用；气泡和轨迹直接按消息来源分类。
