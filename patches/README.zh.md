# DSH 补丁

[English](README.md) | 中文

本目录维护 PaperMoon 必需的 DSH 修改。主仓库的 Gitlink 固定官方基线，[series.json](series.json) 列出补丁和检查。产品行为优先通过 DSH 扩展点和 PaperMoon 插件实现。尽量缩小补丁范围；为保证功能完整、职责清楚，确有必要时允许扩大。扩展时在所属 Note 记录上游缺口、受影响消费者及验证。

`dsh/` 是受管理的检出目录。执行 `pnpm run setup` 前先导出需要保留的修改：该命令会重置已跟踪文件、删除未忽略的未跟踪文件，再应用补丁。运行数据和独立工作应放在此目录之外。初始化和升级操作见[开发文档](../docs/development.zh.md)。

## 组织方式

按维护职责归组，将相关实现、测试和直接契约放在一起，可以跨越文件和包。紧随共享机制变化的小型消费者适配随该机制维护。多项职责共用的汇总内容可以独立归组。

每个受修改的 DSH 文件只归属一份补丁，保存相对固定基线的完整差异，无需沿着中间补丁追踪最终修改。一份补丁可以涵盖多项能力，不要求独立运行。历史由 Git 保留。

职责或共同维护需求变化时，可以合并、拆分、重命名或移动补丁及目录。原职责延续时更新已有补丁，出现独立职责时新增补丁。当前名称、数量和目录层级不构成固定分类。测试、契约和生成产物随归属一起调整。单纯重组需要源码等价验证，不新增决定记录。

在 `series.json` 中登记相对此目录的补丁路径，每条路径只登记一次；补丁为空时，一并删除文件和登记项。清单规定应用顺序。补丁文件及目录必须是仓库内的普通文件和目录，不使用符号链接。清单版本标识格式，不代表 DSH 或补丁修订版本。

## 编辑与导出

以下命令在 PaperMoon 根目录执行。

1. 编辑前运行 `pnpm check:patches:source`。发现差异时，先查明原因再重置检出目录。
2. 在 `dsh/` 中编辑最终源码，保留 DSH 的代码和运行时约束，并更新受影响的测试和直接契约。
3. 用 `git apply --numstat` 查看所属补丁的路径。导出这些路径相对 `HEAD` 的完整差异，包含新归入的文件。新建文件先执行 `git -C dsh add -N -- path/to/new-file.ts`，让 Git 在导出时包含它。
4. 审阅导出结果，更新其他受影响的补丁或调整组织方式，再比较源码并执行相关检查。转移归属时，确保每个文件只保留在一份补丁中。

例如，token-meter 包当前的全部修改归入同一补丁：

```sh
git apply --numstat patches/plugins/token-meter.patch
git -C dsh diff --binary --no-renames HEAD -- \
  packages/llm/token-meter \
  > patches/plugins/token-meter.patch
pnpm check:patches:source
```

只有目录内全部受修改文件都属于该补丁时，才按整个目录导出；否则列出所属文件。应包含先前的全部差异，不能只导出最近一次编辑。代码审阅和静态分析使用受管检出目录中重建的源码。

## 文档与决定

保留源码注释，以及受修改包中必要的双语 README 契约和配对记录。在调用者查阅的位置更新语义、限制和扩展点。审阅两种语言后，使用所检出 DSH 的命令记录配对。

全站架构和参考页面保留上游基线，不描述全部 PaperMoon 扩展。补丁不同步这些页面、相应生成文档或 DSH Agent Note。运行时生成代码、录制快照和测试输入继续维护，包括用作测试数据的 Markdown。

补丁理由保存在主库所属的 [Agent Note](../.agents/notes/README.zh.md) 中。整合旧记录时，保留独有理由、替代方案、约束和验证依据，再修复引用。包契约和决定记录各有一处维护位置。

## 验证与生成产物

| 命令 | 用途 |
|---|---|
| `pnpm check:patches:source` | 在临时检出目录重建补丁，与 `dsh/` 比较，拒绝重复文件归属或未登记源码 |
| `pnpm check:patches` | 比较源码，执行登记的 DSH 检查，再比较一次源码 |

清单中的检查指定 DSH 包脚本及参数数组，执行时不经 shell 拼接。有补丁就必须登记检查。按[测试与交付](../docs/testing.zh.md#dsh-补丁)选择行为测试、录制回放、类型检查、lint 和运行时目录检查。检查不得改写源码或预期结果。全站文档同步不属于此范围。

Host API 可用 `pnpm -C dsh run gen-cordis-catalog --runtime-only` 生成，用 `pnpm -C dsh run verify-cordis-catalog --runtime-only` 检查是否最新。其他运行时目录沿用 DSH 的生成命令。生成后审阅并导出差异；初始化只应用已保存的补丁，不运行生成器。

机械重组时，在改变受管检出目录前，确认重建结果与原有源码一致。行为变化需要相应测试。源码比较排除已忽略的构建产物和运行文件；补丁应用检查新增源码中的空白错误，保留上下文行所需的空格。

## 补丁提升为插件

局部修正默认保留为补丁。补丁中职责完整的一部分功能，可以通过 DSH 扩展点或 profile 组合划清边界、需要由 PaperMoon 独立维护行为，而且源码比上游差异更易维护时，可以考虑提升为插件。

按职责和依赖判断，不以行数、文件数或补丁数量为门槛。提升不要求迁走整份补丁，也不要求复制整个自带插件。修改扩散到共享格式或多个消费者时，应先审查设计。

提升后的插件遵循主库规则。沿用上游代码时保留来源、基线和许可，通过 profile 组合加载并验证其与 DSH 的协作。删除已转移的差异，重新整理剩余修补。[维护决定](../.agents/notes/implemented/architecture/2026-09-18-patch-maintenance.zh.md)记录理由和当前组织方式。
